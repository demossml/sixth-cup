# Касса: «Терминал не авторизован» на экране заказов — причина и что осталось в APK

## Что было

`GET /api/devices/orders/active` (и остальные `/api/devices/orders/*`) требовал **только**
`X-Device-Token` — токен после enroll. В APK enroll не реализован вообще: `OrderApi` шлёт
`X-Evotor-Store-Uuid`, `X-Evotor-Device-UUID`, `X-App-Version-*`, а `X-Device-Token` не отправляет
нигде. Отсюда `401 Unauthorized` и текст «Терминал не авторизован. Перепривяжите кассу», хотя
касса авторизована для каталога, смены и лояльности.

## Что исправлено на backend

`/api/devices/orders/*` теперь принимает оба пути (`middleware/deviceStore.ts`):

1. `X-Device-Token` → устройство из таблицы `devices` (как раньше);
2. `X-Evotor-Store-Uuid` (+ `Authorization` от прокси Эвотора) → точка по
   `evotor_stores.local_store_id`.

Точка определяется по заголовку, поэтому заказы чужой точки не видны. Если связь
«касса ↔ точка» в админке не создана, но в системе ровно одна точка — используется она
(одноточечная установка). Если точек несколько и uuid неизвестен → `404 unknown_store`.

## Что осталось на стороне APK (не блокирует работу)

1. Текст ошибки: `401` → «Касса не привязана к точке. Откройте админку → Касса → Привязать точку
   Эвотор», `404 unknown_store` → «Точка кассы не найдена в 6.7 — привяжите её в админке».
   Сейчас любая из этих ситуаций пишет «Перепривяжите кассу», хотя перепривязка в APK не существует.
2. `enroll`/`X-Device-Token` можно не добавлять: прокси-режим уже работает и совпадает с остальными
   device-запросами. Если добавлять — вместе с обработкой `409` (код уже использован) и `410` (код истёк).
3. `PreorderQueue` уже опрашивает `GET /orders/active` раз в 10 с — менять ритм не нужно.
