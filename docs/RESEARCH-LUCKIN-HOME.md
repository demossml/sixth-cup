Статус: исследование, код не менялся.
Дата: 2026-10 (скриншоты приложения: Luckin SG v1.4.81, Luckin CN v5.6.10).

## Статус реализации (обновлено 2026-11-11)

| Фаза | Статус | Что сделано |

Отклонения от плана:
- «Сегментная шкала» **не делалась**: по решению владельца марки остаются как в прототипе — пустые ячейки не рисуются вообще, показываются только собранные (эффект «стёрли монеткой»). Полоса сохраняет высоту 40 px, чтобы карта не прыгала после первой покупки.
- Купоны не уехали в bottom-sheet: срок годности остался видимым прямо в карточке рельса.

## Текст акции — только из админки (2026-11-11)

Раньше в `CardPage` был зашит фолбэк «Каждый N-й кофе в подарок»: если владелец удалял материал, гость всё равно видел эту надпись. Теперь:

- источник текста — только `promos` с плейсментом **`home_feature`** (админка → раздел **«Контент»** → «Карточка под QR на главной»): `title`, `body`, `cta_label`, `badge`, `image_url`, `product_id`, `sort_order`;
- нет опубликованных материалов и нет купонов → **секции нет вообще**, а не «дефолтная» акция;
- `product_id` из админки задаёт переход на товар, без него — на `/menu`;
- плейсмент `home` (легаси) по-прежнему показывает ровно одну карточку.

Новый компонент `frontend/src/components/DealCard.tsx`: медиа сверху (фото/видео или брендовый градиент с водяным знаком 6·7), бейдж-чип, заголовок, подпись, CTA — всё из данных. Широкая карточка (одна) — медиа слева, рельс (две и больше) — медиа сверху.

Попутно исправлено: подпись поля `sortOrder` в админке говорила «больше = выше», тогда как сервер сортирует `ORDER BY sort_order ASC`. Теперь подпись совпадает с поведением («меньше = выше»).

## 4. Наш текущий главный экран (инвентаризация)

`frontend/src/pages/CardPage.tsx`, порядок блоков:

1. `hero-night` — логотип, (подарок-чип | бейдж «Офлайн»), `progressPhrase`, подпись «Без SMS и регистрации — карта уже ваша», `ProgressStamps`, «Собрано N из 5». Поддерживает `home_hero` как фон.
2. `ActiveOrderBanner` — активный заказ.
3. `InviteNotice` — неприменившееся приглашение.
4. **Карта-пропуск** — QR 112 px, номер карты, кэшбэк, «Открыть QR ›», тап → `QrLayer`.
5. `promo` — одна карточка акции (`home_feature`), до 148 px.
6. Приглашение друга + «От друзей» (две строки в одной карточке).
7. `AppSetup` — «Настроить приложение» / «На экран» / «Сохранить код».
8. Купоны — вертикальный список с датами.
9. Оверлеи: `QrLayer`, `OrderQrScreen`.

Навигация: 3 таба (`Карта`, `Меню`, `Ещё`).

### Наши жёсткие инварианты (ломать нельзя)

- `И1` Карта создаётся сама, без телефона/SMS и без регистрации.
- `И2` **≤ 2 тапа до экрана QR** (карта → полноэкранный QR).
- `И3` Повторный визит офлайн работает: карта + QR из кэша, бейдж «Офлайн».
- `И4` Главный экран укладывается в один вьюпорт 390×844 и не разваливается на 320×568.
- `И5` Все числа прогресса — серверные (`cupsTowardFree`, `freeAvailable`), оптимистичных марок нет.
- `И6` Никаких новых обязательных сетевых запросов на главной.
- `И7` Онбординг не возвращается, если карта есть.

Следствие для редизайна: **правило «1 пришёл — 1 ушёл»**. Экран уже занят; любой новый блок должен заменить существующий, а не добавиться.

### Что реально усиливает нашу концепцию

1. **Порядок «состояние → действие»**: у них hero продаёт, у нас hero — это паспорт карты. Приём: сделать hero визуально «пропуском» (фото, скругление, чёткая иерархия), но оставить внутри прогресс и «Собрано N из 5».
2. **Число вместо абстракции**: «45 points to Silver» ↔ наше «ещё 2 стакана до подарка». Дешёвая правка текста + шкала.
3. **Один акцент и светлый фон**: их фон почти белый, акцент один; у нас сейчас много белых карточек на белом. Правка только CSS-токенов.
4. **Статус всегда виден**: плавающий трекер заказа — прямое улучшение, снимает необходимость искать «что с моим кофе».
5. **Секция + «Ещё»**: не вываливать все купоны на главную.

## 6. План (по фазам, каждая — отдельный коммит, с гейтами)

Гейты после каждой фазы: `npm run typecheck` (3/3), `npm test -w frontend` (101), `npm test -w frontend-admin` (252), `npm test -w backend` (940), `npm run build`, ручная проверка на `:4174` в 390×844 **и** 320×568.

### Фаза 0 — только токены и типографика (риск: минимальный)
- светлый фон страницы, один акцент, радиусы 20/24, тени мягче, заголовки секций единого размера;
- ничего не двигаем, блоки не добавляем.
- Гейт: визуальный diff скриншотов до/после, все тесты зелёные.

### Фаза 1 — hero как «пропуск» (риск: средний)
- приветствие по времени суток + имя (`displayNickname`) одной строкой;
- сегментная шкала вместо/поверх `ProgressStamps` + подпись «ещё N стаканов до подарка»;
- сохранить «Собрано N из 5» и `aria-label`;
- проверить И4 (высота не выросла > 8 px).

### Фаза 2 — секция акций + карусель (риск: средний)
- `promo` → заголовок секции «Акции» + «Ещё» + горизонтальный рельс (1–3 карточки из `content`);
- если `content` пуст — секция не рендерится (никаких пустых заголовков);
- купоны переезжают в тот же рельс, детали (срок) — в bottom-sheet.

### Фаза 3 — сетка 2×2 (риск: высокий, только после 0–2)
- `Купоны · Друзья · Кэшбэк · Стаканы` одной сеткой, вместо трёх блоков;
- тап по плитке ведёт на существующие роуты (`/promos`, `/invite`, `/me`, hero-якорь);
- **обязательно**: дата срока купона доступна в ≤ 1 тап.

### Фаза 4 — плавающий трекер заказа (риск: средний)
- `ActiveOrderBanner` → fixed-пилюля над таб-баром, `safe-area-inset-bottom`;
- контент получает нижний паддинг, чтобы ничего не перекрывалось;
- проверить, что при отсутствии заказа ничего не рендерится и не «съедает» место.

### Фаза 5 (опционально, только по запросу) — плитки-действия
- `Меню` / `Пригласить` под hero **взамен** блока приглашения (не в дополнение);
- если не влезает в 320×568 — не делаем.

### Чего в плане нет и почему
- уровней/поинтов/credits — другая модель лояльности, потребует бэкенда и затронет модуль себестоимости;
- 5 табов, регистрации, доставки, оплаты — прямое нарушение концепции;
- дублирующей карточки прогресса — прогресс должен жить в одном месте.

## 8. Итог одной фразой

Копируем **оформление состояния** (фото-герой со скруглением, число вместо абстракции, сегментная шкала, светлый фон + один акцент, секция с «Ещё», плавающий статус), но **не копируем приоритеты**: у Luckin главная — витрина заказа с регистрацией, у нас — карта без регистрации, где QR должен оставаться в двух тапах и работать офлайн.
