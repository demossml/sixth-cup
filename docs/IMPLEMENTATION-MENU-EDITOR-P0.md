### Побочные исправления, без которых P0 не работал

- `blockPayload` вырезал новые поля — `uppercase`/`locked` не сохранялись; теперь входят в payload.
- Схема темы принимала только 7 символов (`#RRGGBB`) — иначе альфа не сохранялась; расширено до 9.
- Клиентский резолв не повторял серверную чистку названия → редактор и PDF показывали разное; исправлено.
- Шрифты PDF искались только относительно бандла (`../../../assets/fonts`); при запуске `dist/index.js` из другой папки экспорт падал с `ENOENT`. Теперь каталог ищется по списку кандидатов.
- Выбор блока не переключал правую панель на «Блок» — теперь переключает.

## 4. Что осталось (и почему)

- **P1-31** — полный протокол S1–S8 (8 сценариев × время и клики); серверные и браузерные метрики уже сняты.

Всё остальное из P1 закрыто. Заметки на будущее по этим двум задачам:
- CMYK — DeviceCMYK без ICC-профиля; если типография потребует конкретный профиль (например, Coated FOGRA39), понадобится ghostscript или littlecms на сервере.
- Свой шрифт — проверяются кириллица и ₽, но не лицензия: ответственность за права на файл остаётся на владельце.

### Замер сценария «с нуля до PDF» (P1-31, частично)

Прогон на копии боевой базы, локальный сервер, 1 поток:

| Шаг | Время |
|---|---|
| Создать макет (API) | 25 мс |
| «Собрать из каталога» → 9 блоков | 5 мс |
| Экспорт PDF `print` + bleed 3 мм | 101 мс (первый прогон, прогрев шрифтов), далее 12–16 мс |
| Сохранить версию | 3 мс |
| **Итого серверная часть** | **131 мс** |

Плюс замеры из браузера: TTI редактора 34–43 мс, 56 FPS при 100 блоках. Полный протокол S1–S8 (8 сценариев × время и число кликов) ещё не снят — он требует ручных прогонов с дизайнером.
- **P1-31** закрыт частично: замеры TTI/FPS/PDF автоматизированы (`?perf=1`), но протокол «8 сценариев × время и клики» ещё не снят.

### Исправлено попутно: миграции не применялись при запуске из `dist`

При запуске `node dist/index.js` каталог миграций искался как `./migrations` относительно бандла — в сборке он пустой (вложенная папка без `.sql`). То есть **новая база из бандла поднималась без миграций**. Теперь каталог ищется по списку кандидатов, а `npm run build` копирует `.sql` в `dist/migrations`. Проверка: чистая база + `dist/index.js` → применено **58** миграций.
- **P2 и P3** — не начаты, это отдельные месяцы (см. §7 плана R2).
- **Пипетка (P1-5)** сделана с честным фолбэком: в Chromium работает `EyeDropper`, в остальных браузерах кнопка пишет «Пипетка есть только в Chrome/Edge — введите HEX вручную».

## 5. Как проверить самому

```bash
npm install
npm run typecheck && npm run build
npm run test -w backend        # 805
npm run test -w frontend-admin # 142
npm run dev                    # client :5173 · admin :5174 · API :3000
```

В редакторе:

1. **Объёмы.** «Собрать лист из каталога» на каталоге с группами — «Капучино» даёт один блок с тремя ценами.
2. **Цвет.** Оформление → поле «Фон листа»: вписать `#12AB34`, потом `#12AB344D` — фон станет полупрозрачным, под полем появится контраст.
3. **Раскладка.** Shift+клик по двум блокам → в тулбаре появятся выравнивания; тянуть блок к центру — появится красная линия.
4. **Права.** Правый клик по блоку → меню; «Закрепить» и попробовать сдвинуть.
5. **Замеры.** Открыть `…/menu-layouts/<id>?perf=1`, подвигать блок, скачать PDF — числа появятся в консоли.

## 6. Риски и заметки

- **Группы объёмов.** Работает для товаров с `group_id`; если в каталоге вариант заведён без группы (три товара без `group_id`), они по-прежнему лягут тремя блоками — это данные, а не редактор.
- **Альфа в PDF** для фона смешивается с белой бумагой (печать не умеет прозрачность); для текста и акцента используется `fillOpacity`.
- **`?perf=1`** — диагностика, в обычной работе ничего не логирует.
- Прод-каталог в этой работе не менялся; проверки шли на копии базы (`/tmp/qa-menu.db`).
