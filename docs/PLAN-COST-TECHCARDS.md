## 2. Целевая модель данных (миграция `062_cost_techcards_v2.sql`)

### 2.1 Ингредиент = позиция склада

`stock_items` дополняется:

| Поле | Тип | Зачем |
|---|---|---|
| `kind` | `raw` / `unit` / **`semi`** | заготовка (D4) |
| `weight_per_pc_kg` | REAL NULL | «1 шт = 0,012 кг» (G15, паттерн Meez) |
| `density_kg_l` | REAL NOT NULL DEFAULT 1 | перевод литров в кг (iiko требует, иначе нули) |
| `manual_cost_kop` | INTEGER NULL | ручная цена-фолбэк, когда приходов нет |
| `nutri_*` (kcal, protein, fat, carbs) | REAL NULL | КБЖУ на 100 г/мл (G10) |
| `allergens` | TEXT | JSON-массив |

`cost_ingredients` **не удаляем**: помечаем `deprecated_at` и однократно сливаем в `stock_items` (§6).

### 2.2 Техкарта

```
tech_cards(id, name, kind 'dish'|'semi'|'modifier',
           output_qty REAL, output_unit 'kg'|'l'|'pcs',   -- норма закладки (G3)
           product_id INTEGER NULL,                        -- связь с каталогом/кассой
           category_id, method_text, status 'draft'|'active'|'archived',
           write_off_mode 'ingredients'|'semi'|'semi_then_ingredients'|'none',  -- G11
           retail_price_kop, markup_pct, created_at, updated_at)

tech_card_versions(id, card_id, valid_from INTEGER, note, created_at, created_by)
    -- D3: новая версия только при смене состава; правка текста — журнал

tech_card_lines(id, version_id, sort_order,
                stock_item_id INTEGER NULL,        -- ингредиент или заготовка (kind='semi')
                child_card_id INTEGER NULL,        -- либо прямая ссылка на карту заготовки
                qty_brutto REAL NOT NULL,          -- в базовых единицах позиции
                loss_cold_pct REAL DEFAULT 0,      -- допускает отрицательные (варка)
                loss_hot_pct REAL DEFAULT 0,
                qty_netto REAL,                    -- вычисляется или вводится
                qty_yield REAL,                    -- вычисляется или вводится
                line_role 'base'|'optional',       -- как сейчас
                CHECK (stock_item_id IS NOT NULL OR child_card_id IS NOT NULL))
```

Инварианты на сохранении (проверяются в `costCalc.ts`, не в БД):
`qty_brutto > 0`, `qty_netto = brutto × (1 − loss_cold/100)`, `yield = netto × (1 − loss_hot/100)`;
запрет циклов (`A → B → A`) обходом в глубину; запрет `child_card_id === card_id`.

### 2.3 История цен

```
stock_item_cost_history(id, stock_item_id, at INTEGER, cost_kop REAL,
                        source 'invoice'|'inventory'|'manual', ref_id INTEGER)
    -- пишется при проведении накладной (`/purchases/invoices/:id/post`) и вручную
```

### 2.4 Проекция для склада (D6)

`product_stock_norms` перестаёт быть источником: заполняется триггером-функцией
`projectTechCard(cardId)` — из активной версии карты, у которой `product_id` заполнен.
`product_recipe_modes.mode` наследуется из `tech_cards.write_off_mode`
(`ingredients→raw`, `semi→piece`, `none→none`). Старые эндпоинты `/stock/recipes` читают проекцию —
склад и себестоимость больше не расходятся.

### 2.5 Модификаторы

Модификатор (сироп, альтернативное молоко) — тоже `tech_card` с `kind='modifier'`; в карте напитка
он либо строка-ингредиент, либо отдельная карта, связанная через `child_card_id` (D5).

## 3. Расчётный движок (`backend/src/modules/admin/costCalc.ts` — новый файл)

### 3.1 Себестоимость строки

```
pricePerBase = weightedCost(item)            // §3.3, копейки за базовую единицу
qtyBase      = toBaseUnits(qty_brutto, item) // кг/л/шт, через weight_per_pc_kg и density
lineCost     = qtyBase × pricePerBase
```

### 3.2 Выход и потери (D1, G2) — двунаправленно

Пользователь вводит **любые два** из (брутто, нетто, выход) или проценты — остальное считается:

```
netto = brutto × (1 − lossCold/100)
yield = netto  × (1 − lossHot/100)
lossCold = (1 − netto/brutto) × 100        // если введено нетто
lossHot  = (1 − yield/netto) × 100         // если введён выход
```

Отрицательные потери допустимы (`варка риса`). Себестоимость считается **по брутто** (как в iiko).

### 3.3 Средневзвешенная цена (D2)

```
период = max(дата последней полной инвентаризации, now − 90 дней)
cost = Σ(qty × unit_cost_kop) / Σqty   по проведённым накладным в периоде
если период пуст → последняя известная цена из stock_item_cost_history
если истории нет  → stock_items.manual_cost_kop
если и его нет    → null  → бейдж «нет цены», себестоимость «—» (как звёздочка в iiko)
```

### 3.4 Себестоимость порции и экономика

```
cardCost     = Σ lineCost (+ для заготовок: qty × costPerUnit(childCard))
costPerUnit  = cardCost / output_qty        // норма закладки (G3)
foodCostPct  = costPerUnit / (retail_price_kop/100) × 100
marginRub    = retail − costPerUnit
```

Округления: всё в копейках (`*_kop`), как в существующем коде; на экран — рубли с 2 знаками.

## 6. Миграция существующих данных (одна транзакция, с бэкапом)

1. Слить `cost_ingredients` → `stock_items`: по имени (без учёта регистра) и единице; недостающие создать
   (`kind='raw'`, цена = `pack_price_kop / pack_qty`).
2. `cost_recipes` → `tech_cards` (v1, `valid_from = created_at`), `cost_recipe_lines` → `tech_card_lines`
   (`qty_brutto = qty`, потери 0, `output_qty = 1`, `output_unit` из единицы карты).
3. `product_stock_norms` → сверить с картами: где карта есть — источник карта; где норм нет — оставить как есть.
4. `product_recipe_modes` → `tech_cards.write_off_mode` (обратное соответствие).
5. Заполнить `stock_item_cost_history` первым срезом текущей цены (source='manual').
6. Метка `cost_ingredients.deprecated_at`, `cost_recipes.migrated_card_id`.

Проверка миграции: `SELECT` сверка количества ингредиентов/карт до и после + тест «на копии боевой базы».

## 8. Что сознательно не делаем в v1

- Печать ТТК/ОП-1 и любые печатные формы (решение владельца), но модель хранит всё нужное.
- Партии FIFO и учёт по партиям (выбран средневзвешенный D2).
- Мультиточечные закупки и цены по точкам (1–5 точек, одна база).
- План-факт списаний остаётся в «Складе»; в карту не тащим.
- ABC-анализ меню и меню-инжиниринг — отдельной задачей после.
- КБЖУ в гостевом интерфейсе (в v1 — только расчёт в карте).

## 9. Риски и откат

| Риск | Оценка | Что делаем |

## 11. Как проверим, что получилось

1. **Эталонная карта**: капучино 250 мл — зерно 18 г, молоко 150 мл, стакан 1 шт (вес штуки задан),
   сироп 20 г как модификатор. Себестоимость сходится с ручным счётом до копейки.
2. **Заготовка**: «молоко взбитое» 5 л из 5,2 л молока (потери 3,8 %) → блюдо берёт 150 мл заготовки;
   изменение цены молока меняет себестоимость блюда на следующий день.
3. **Версия**: с 1 декабря сироп дороже — новая версия карты, до 1 декабря считается старая.
4. **Сигналы**: удалить цену у ингредиента → карта попадает в «Сигналы», себестоимость «—».
5. **Склад**: продажа на кассе уменьшает остаток по новой норме; `/stock/recipes` показывает то же,
   что карта (нет расхождений).
6. **Эвотор**: `cost_price` в каталоге равен `costPerUnit` карты.
7. **Массовая замена**: карамель → «карамель солёная» с коэффициентом 0,9 в 20 картах, ни одна не сломалась.
