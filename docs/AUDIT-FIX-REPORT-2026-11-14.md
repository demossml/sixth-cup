## Не закрыто данными (не код)

- **Поставщики и первая накладная на проде.** Агент не создаёт бизнес-данные на бою. Путь готов: «Закупки → Поставщик» → «Новая накладная» → «Создать черновик» → «Провести».
- **Ручная допривязка техкарт.** Однозначные совпадения имён связываются кнопкой «Связать по названию» (`POST /cost/tech-cards/link-products?dry=0`); спорные (0 или 2+ товара) остаются человеку — на проде это надо нажать один раз и посмотреть `unresolved`.
- **Составы схем добавок.** Пустые схемы теперь видны, но наполнить их контентом (какие сиропы/топпинги) может только владелец.
- **Кэшбэк** начисляется только с покупок приглашённых (3 %) — это правило продукта, не дефект; в UI теперь подписано.

## Что изменилось в поведении API (важно при деплое)

- `POST/PUT /api/admin/cost/tech-cards` для `kind = dish | modifier` требует `productId` (400 без него).
  Импорт техкарт пишет в БД напрямую и не затронут; заготовки (`semi`) — как раньше.
- Дефолт периода у `/analytics/series|by-store|overview|heatmap` — **7 дней** (раньше series 24 ч, overview/heatmap 30 дн).
- `/analytics/overview` и `/analytics/heatmap` теперь реально слушают `period` (раньше heatmap игнорировал его при отсутствии параметра).
- `/cost/tech-cards` отдаёт `productName`, `catalogPriceRub`, `retailSource` и `totals.withoutProduct`.
- `/stock/balances` и `/stock/snapshot` отдают блок `accounting`.
- `/customers/:id` отдаёт `cashbackPercent`.
- Новый `GET /api/admin/evotor/failed-docs?limit&store` (read-only).

## Риски / регрессии

- **Цена продажи в техкартах** теперь берётся из товара: у карт, привязанных к товару, фудкост и маржа
  изменятся в момент привязки. Это цель правки, но владелец увидит другие цифры — в UI поле цены помечено
  «используется цена товара из меню».
- Легаси-карты без товара продолжают читаться (меню-инжиниринг ищет продажи по имени) — покрыто тестом.
- Смена дефолта периода аналитики меняет стартовую картинку на «Аналитике» и в «Сравнении» (там периоды
  выбираются явно, поведение не менялось).
- Склад: баннер показывается только при `postedInvoices = 0` — на базе, где приходы уже есть, ничего не появится.
