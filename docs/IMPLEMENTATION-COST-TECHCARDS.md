# Себестоимость / техкарты — история первой версии (v1)

> Актуальная версия раздела — v2: `docs/IMPLEMENTATION-COST-TECHCARDS-V2.md`
> (техкарты на складе, версии, средневзвешенная цена, проекция в кассу).
> Этот файл описывает первую версию; её эндпоинты продолжают работать как есть.

## Возможности
- CRUD ингредиентов (добавление, редактирование, **удаление** если не в рецептах)
- Категории «+»
- Рецепты с base/optional; **красные** строки без цены **не входят в себес**
- **Импорт техкарты**: Excel `.xlsx` / CSV / вставка текста
- ИИ-разбор прайса (черновик → подтверждение)
- Сводка + CSV

## API
- `DELETE /api/admin/cost/ingredients/:id`
- `POST /api/admin/cost/import/techcard-text` `{ text }`
- `POST /api/admin/cost/import/techcard-file` multipart `file`
- остальные `/cost/*` как в v1

## Зависимость
- SheetJS (`xlsx`) в backend — только чтение Excel при импорте техкарты.
  Ставится с вендорского CDN пропатченной версией: `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`
  (в npm-версии 0.18.5 две незакрытые уязвимости — Prototype Pollution и ReDoS, «no fix available»).
  Загрузка файла ограничена 5 МБ, эндпоинт админский (`X-Admin-Token`).

## Исправления после наката архива
- `parseIngredientsFromText`: `\b` в JS работает только по ASCII, поэтому «1 л» и «200 г» не распознавались
  (тест падал). Границу слова заменили на `(?![а-яёa-z])`, альтернативы — `кг|г`.
- `techcardImport.ts`: невалидный ключ объекта `шт.: 'pcs'` ронял парсер на этапе сборки — убран
  (`normalizeUnit` и так срезает точки).
- Лимит размера файла техкарты — 5 МБ.

## Деплой
1. Накатить архив
2. `npm install` (подтянет xlsx)
3. build + restart API (миграция 056)
4. Админка → Себестоимость → Импорт техкарты
