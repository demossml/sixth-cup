## 1. Правила работы (не нарушать)

1. **Один этап = один прогон.** Не начинать следующий, пока GREEN предыдущего не подтверждён.
2. **Палитра бренда.** `#FFFFFF` / `#D9E6F5` / `#0B4A8D`. Крем `#F6F3EE`, `#EDE7DC`, `#EEE7DA` и `#002FA7` не возвращаем.
3. **Композиция 1:1 с макетом** — структура, порядок блоков, размеры, поведение; цвета — наши.
4. **Всё редактируется из админки.** Если для экрана нужны данные — сначала поля в админке, потом UI.
5. **Никаких «оптимистичных» обещаний.** Если касса ещё не умеет — в UI пишем честно.
6. **Регресс запрещён.** После каждого этапа:
   ```bash
   npm run typecheck && npm run build
   npm run test -w frontend && npm run test -w frontend-admin
   cd backend && DB_PATH=$(mktemp -u /tmp/t-XXXX.db) npx vitest run
   ```
7. **Живой прогон обязателен** для этапов, меняющих заказ: backend в `NODE_ENV=production` отдаёт `dist`,
   PWA на том же origin, админка — собранный `dist` за прокси.
8. **Миграции только аддитивные**, с rollback-файлом. Не трогать существующие данные.
9. Коммит/push — по слову владельца; после каждого этапа отдельный коммит с внятным сообщением.

### S1 — Бонусы в заказе: quote и `preorders.benefit` (backend) (1.5 дня)

**Зачем:** пункт 6 и 15 таблицы. Сейчас сумма в заказе — «оценка» и может расходиться с экраном;
подарок/ваучер живут только на кассе по QR карты.

**Модель (переиспользуем существующее):** `modules/loyalty/reservations.ts` уже умеет
`resolveAndReserve` (подарок + кэшбэк + ваучеры) и `consumeReservation` на SELL.

1. Миграция `045_preorder_benefit.sql`:
   ```sql
   ALTER TABLE preorders ADD COLUMN benefit_json TEXT;     -- что выбрал гость
   ALTER TABLE preorders ADD COLUMN reservation_id TEXT;   -- ссылка на резерв лояльности
   ALTER TABLE preorders ADD COLUMN quote_total INTEGER;   -- сумма после бонуса
   ALTER TABLE preorders ADD COLUMN quoted_at INTEGER;
   ```
2. `POST /api/orders/quote` (гость, JWT):
   вход `{storeId, items[], benefit?: {kind:'gift'|'voucher'|'cashback', voucherId?}}`,
   выход `{ok, items:[{unitPriceEstimate, sum}], discount, total, benefit:{...}, available:{gift, cashback, vouchers[]}}`.
   Правила: одно правило за раз; подарок — один напиток из корзины с `freeEligible`;
   ваучер — из `activeVouchers`; кэшбэк — не больше остатка. Ошибки: `benefit_not_available`, `benefit_stale`.
3. `POST /api/orders` принимает `benefit` и `quoteToken` (подпись quote, TTL 10 мин):
   - создаёт резерв (`resolveAndReserve` по коду карты гостя, привязка к `orderId`),
   - пишет `benefit_json`, `reservation_id`, `quote_total`;
   - при расхождении суммы с quote → `409 quote_stale` (гость пересчитывает).
4. Касса: `GET /api/devices/orders/:id` и `resolve` отдают `benefit` и состав с ценами;
   `mark-paid` закрывает резерв (`consumeReservation` по `orderId`). Повторный вызов идемпотентен.
5. Отмена/истечение заказа → резерв освобождается.

**Тесты:** новый `preorder-benefit.test.ts` — 10+ кейсов (подарок, ваучер, кэшбэк, чужой ваучер,
истёкший ваучер, повторное применение, отмена освобождает, расхождение quote, лимит кэшбэка).

**GREEN:** quote и заказ дают одинаковые цифры; резерв закрывается при оплате и освобождается при отмене.

**Риск:** пересечение с SELL-логикой. Снимаем: резерв привязан к `orderId`, `consumeReservation` не меняем,
только добавляем вызов; всё под фичелагом `orders.benefit` в `app_settings` (по умолчанию выкл. до приёмки).

### S9 — Медиа товара: фото **или видео** 4:5 (админка + PWA) (1.5 дня)

**Зачем:** пункт 12. Решение владельца: в админку будут грузить **фото или видео** — те же, что для меню.

1. Миграция `047_product_media.sql`:
   ```sql
   ALTER TABLE products ADD COLUMN media_type TEXT NOT NULL DEFAULT 'image';  -- image | video
   ALTER TABLE products ADD COLUMN video_url TEXT;
   ALTER TABLE products ADD COLUMN poster_url TEXT;   -- кадр-обложка для видео
   ```
   `image_url` остаётся как есть (обратная совместимость).
2. Админка (карточка товара, блок «Фото товара» → «Медиа товара»):
   - загрузка фото (JPEG/PNG/WebP ≤ 2 МБ) или видео (MP4/WebM ≤ 15 МБ, H.264);
   - проверка пропорций 4:5 (предупреждение + кроп-рамка на `<canvas>` для фото);
   - для видео — выбор кадра-обложки (первый кадр по умолчанию), переключатель «фото/видео».
3. PWA `ProductPhoto`:
   - `media_type='video'` → `<video muted loop playsinline preload="metadata" poster=…>` без автозвука,
     пауза вне экрана (IntersectionObserver), `reduced-motion` → показываем постер;
   - фото — `srcset` 400w/800w, `loading=lazy`, `decoding=async`;
   - заглушка прежняя (ice-градиент + маскот), пока медиа нет.
4. Каталог и корзина: видео не грузится на карточках сетки (только постер), полное видео — на экране товара.

**Тесты:** чистая `mediaOf(product)` (тип/poster/размеры), PWA — рендер без утечек (пауза при уходе).

**GREEN:** товар с видео показывает постер в сетке и видео на карточке; вес списка не растёт.
