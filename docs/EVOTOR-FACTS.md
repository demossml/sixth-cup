- **Даты**: `gtCloseDate` / `ltCloseDate` принимают только `YYYY-MM-DD` (без времени — иначе HTTP 400 `invalid_format`). `ltCloseDate` **исключительная** граница → для «сегодня» отдавать завтрашнюю дату.

  - `Мой магазин` (…8488) — OK, 3 документа
  - `Твардоского` (…A33B) — HTTP 402 «application is not paid/installed on all devices»

## 2026-10-06 catalog sync architecture

- A 6.7-created product starts with a local product id and no Evotor UUID.
- The first outbound sync uses Cloud CREATE without an id; Evotor Cloud assigns the product UUID.
- The returned UUID is stored per `(store_uuid, product_id)` and reused for all later PUT updates.
- `article_number=sc-<local_product_id>` is a stable recovery key used to find a product if the CREATE response is lost.
- Incoming Evotor products are upserted by `(store_uuid, evotor_uuid)`; unknown remote products become `EVOTOR_IMPORT`.
- Product recipes, toppings and 6.7 business flags are sent separately as `ProductExtra`; the Extra UUID may use UUIDv5, but Evotor product UUIDs are never generated by 6.7.
