## Канон `sc.preorder` для APK-агента

1. `sc.preorder` = `order.id` (uuid заказа) — единственный источник для списания льготы предзаказа.
2. `sc.ord` = номер очереди (queue). Клад **order id** в `sc.ord` считается ошибкой; backend принимает
   такое значение только как legacy-fallback (uuid-заказ существует) и пишет deprecation в лог.
3. Цены и состав заказа считает сервер; касса не присылает `priceRub` добавок как истину.
4. Enroll: код живёт 15 минут, одноразовый, публичный ключ 32–64 символа; лимиты по коду и IP.

Документ: `docs/PREORDER-SC-CANON.md`.

## ASSUMPTIONS

1. **P0-4**: challenge-proof для публичного ключа не вводился — контракт enroll с APK не менялся.
   Риск закрыт TTL 15 мин, одноразовостью кода, форматом ключа и лимитами (5/15 мин по коду, 10/10 мин по IP).
2. **P2-4**: пункт аудита сформулирован как «metrics: imported в push». `imported` — счётчик импорта
   каталога, он отдаётся в pull-метриках (`pulled.imported`). Реализована наблюдаемость доставки push
   (подписки/живые/отозванные/падающие/доставленные) + исключение в health админки.
3. **P2-8/9**: отдельного «welcome»-эндпоинта нет — welcome-ваучер выдаётся бонусным механизмом по факту
   оплаченной покупки, поэтому лимит на него не добавлялся; лимиты поставлены на quote,
   push-subscribe и recovery.
4. **P1-6**: выбран минимальный безопасный шаг (`token_version`), полный переход на access/refresh
   пары не делался — это отдельный рефакторинг авторизации.
5. Исходные `PLAN-AUDIT-FIXES-67-ALL.md` и «пакет аудита» на диске отсутствуют; работа велась по тексту
   промпта `2n.md`, якоря проверялись по коду.
