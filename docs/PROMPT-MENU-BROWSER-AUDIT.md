# ПРОМПТ ДЛЯ ВНЕШНЕГО АГЕНТА: аудит конструктора «Макет меню» только через браузер + план развития до «10 из 10»

**Кому:** внешнему агенту с доступом к браузеру (скриншоты, клики, ввод, devtools-view допустим только для проверки консольных ошибок и размеров).
**Куда:** прод-админка `https://admin.67coffee.ru`, раздел **«Макет меню»** (`/menu-layouts`).
**Токен администратора:** передаётся **отдельным сообщением** вместе с этим заданием. В отчёте токен не цитировать, в файлы и скриншоты не попадать.
**Язык отчёта:** русский.
**Ожидаемое время:** 4–6 часов активной работы. Это не «пройтись по кнопкам», а полноценный продуктовый аудит + исследование рынка + проектирование развития.

## 0. Паспорт задания (прочитай первым)

Мы делаем **редактор печатного меню** — по сути «Фигма для меню кафе»: лист A3/A4/A5/1:1/16:9, блоки (позиция каталога, категория, текст, картинка, логотип, разделитель), свободное перетаскивание, слои, темы, экспорт в PDF для типографии.

Сейчас это «10 из 10 по нашим внутренним меркам», но по факту мы хотим **10 из 10 по меркам Figma / Canva / Adobe Express** — то есть инструмент, в котором владелец кофейни без дизайнера делает меню за 15 минут и не упирается в «а такого цвета нет», «а выровнять нельзя», «а повернуть нельзя».

Твоя работа состоит из трёх равных по важности частей:

| Часть | Результат |
|---|---|
| **A. Аудит «что работает / что не работает»** | Проверенный по шагам список: работает / работает частично / не работает / не проверено — с доказательствами |
| **B. Исследование рынка и библиотек** | Сравнение с Figma, Canva, Adobe Express, VistaCreate/Marq, конструкторами меню; подбор конкретных библиотек под наш стек с лицензиями и оценкой рисков |
| **C. План развития** | Пофазовая дорожная карта с задачами, оценками, критериями приёмки и метриками — такой подробности, чтобы по нему можно было нарезать тикеты и сразу делать |

Отчёт без части B и C **не принимается**. Отчёт вида «всё в целом работает, есть мелкие недочёты» **не принимается**.

## 1. Жёсткие правила (нарушение = задание не принято)

1. **Только браузер.** У тебя нет доступа к репозиторию, к серверу, к базе. Не ищи исходники, не открывай `view-source` с целью «понять код», не вызывай API напрямую (`curl`, `fetch` из консоли), не подбирай внутренние эндпоинты. Всё, что ты утверждаешь, должно быть видно в интерфейсе.
2. **Devtools — только как измерительный прибор.** Разрешено: консоль ошибок, network для проверки, что сохранение реально уходит, измерение размеров/контраста. Запрещено: править состояние приложения через консоль и выдавать это за работу UI.
3. **Прод, реальные данные.** Это боевая админка. Ничего не удаляй из существующего. Всё тестовое создавай с префиксом `QA-` и удаляй после проверки (список созданного/удалённого — в отчёт).
4. **Каталог и цены.** Доступ полный, но правило простое: реальные товары и цены не менять. Нужен товар для экспериментов — создай `QA-ТЕСТ ...`, проверь, удали/верни как было. Каждое изменение каталога — в журнал отчёта (что, где, до/после).
5. **Никаких выводов без доказательства.** Каждое «не работает» = шаги 1-2-3 + ожидание + факт + скриншот + браузер/разрешение/время. Нет доказательства — пункт идёт в «не проверено», а не в «не работает».
6. **Не путать «нет» и «не нашёл».** Если функции не видно — напиши, где искал (какие панели/меню/табы открыл). «Не нашёл» — это тоже результат, но он должен быть честным.
7. **Не загружать в сторонние сервисы (Figma, Canva и т. п.) реальные фото и данные клиента.** Для сравнений — только нейтральные картинки-заглушки и вымышленные названия.
8. **Не менять пароли, не менять настройки системы, не публиковать ссылки.** Экспортированные PDF не выкладывать в интернет.
9. Токены, персональные данные, телефоны клиентов — не попадают в текст отчёта и на скриншоты (замазывай/обрезай).
10. Если что-то не удаётся из-за прав/токена/лимитов — фиксируй как блокер доступа, не обходи.

## 2. Что именно проверяем (карта продукта, которую надо подтвердить или опровергнуть)

Раздел **«Макет меню»**:

- **Список макетов** — карточки/превью, статус, счётчик замечаний, создание, дублирование, удаление.
- **Форматы листа** — A4 портрет/альбом, A3 портрет, A5, 1:1, экран 16:9.
- **Редактор (десктоп ≥1024 px):** слева каталог и слои, в центре лист (зум, сетка, безопасная область, страницы), справа «Оформление» и «Свойства блока».
- **Редактор (телефон <1024 px):** вкладки «Превью / Состав / Дизайн / PDF», выбор блока тапом, координаты полями X/Y/W/H.
- **Блоки:** `product`, `category`, `text`, `image`, `logo`, `divider`; у блока — координаты в процентах, zIndex, поворот, скрытие, свои текст/цена/фото, бейдж, размер шрифта, выравнивание, жирность.
- **Каталог → лист:** «собрать из каталога», раскладка в 2 колонки, поиск/фильтр по категориям, доступность позиций.
- **Цены:** live (из каталога) / frozen (снапшот), баннер «цены изменились», «обновить с каталога», свои цены (`priceText`, `priceRubOverride`), объёмы («250 мл · 350 мл»).
- **Оформление:** тема, фон (цвет или картинка + затемнение), палитра бренда, шрифты, орнаменты/декор.
- **Экспорт:** PDF `print` (поля, метки реза, bleed 3 мм) и `screen`, поведение при блокерах (409 → список → «всё равно скачать»), имя файла, многостраничность.
- **Надёжность:** автосохранение, статус «Сохранено / Есть изменения / Не сохранено», undo/redo (заявлено 100 шагов), конфликт двух вкладок, сохранность после перезагрузки.
- **Клавиатура:** стрелки (0,5 %, с Shift — 5 %), `Delete`, `Alt+Delete` (скрыть), `⌘Z` / `⌘⇧Z`.
- **Возможные дополнительные зоны:** шаблоны, мастер создания, «места»/точки, ИИ-помощник. Если найдёшь — проверь тоже, отметь как «вне заявленного скоупа, но есть в UI».

**Вне скоупа:** гостевой PWA-интерфейс (`app.67coffee.ru/menu`), разделы «Меню», «Группы меню», «Товары меню» и аналитика. Их не аудируем — только используем как источник тестовых данных. Если по ходу выяснится, что без них нельзя проверить конструктор (например, нет товаров), — отметь это, но не расширяй аудит.

## 3. Часть A. Аудит: как проверять

### 3.1. Матрица прогонов

Каждый чек-пункт прогоняется минимум на:

| Окружение | Когда |
|---|---|
| Chromium 1440×900 | основной прогон, 100 % чек-листа |
| Chromium 1024×768 | проверка границы «десктоп/мобилка» |
| Chromium 390×844 (эмуляция телефона) | весь мобильный чек-лист |
| Второй браузер (Firefox или Safari) | выборочно: сохранение, drag, PDF, горячие клавиши |

Дополнительно: масштаб 200 % (проверка вёрстки), клавиатура без мыши (Tab/Enter/стрелки/Escape), режим «уменьшенная анимация» если доступен.

### 3.2. Данные для теста

Создай 2–3 макета:

1. `QA-Базовый A4` — 15–25 блоков, все типы, 2 колонки.
2. `QA-Стресс A3` — максимально много блоков (цель — 60–100, если продукт позволяет), проверка производительности.
3. `QA-Границы` — блоки у краёв, минимальные размеры, длинные названия, блок без фото, позиция без цены, скрытая позиция.

### 3.3. Формат фиксации каждой проверки

Таблица: `ID | Проверка | Ожидание | Факт | Статус (OK / PARTIAL / FAIL / N/A / NOT TESTED) | Severity | Доказательство (файл) | Заметка`.

**Severity:**
- **S1** — блокер: данные теряются, задачу нельзя выполнить, PDF битый/неверный.
- **S2** — крупно: есть обходной путь, но он неочевиден/долгий; ломает доверие к результату.
- **S3** — средне: неудобно, но работу не останавливает.
- **S4** — косметика/полировка.

## 4. Чек-лист аудита (минимум 120 пунктов, каждый — со статусом и доказательством)

Пункты ниже — обязательный минимум. Добавляй свои (помечай `+`), если находишь поведение, которого нет в списке.

### Z0. Вход и список макетов
- `C0.1` Вход по токену: успешный вход, неверный токен, пустой токен, истёкшая сессия (перезагрузка после выхода).
- `C0.2` Раздел «Макет меню» открывается из навигации; хлебные крошки/заголовок корректны.
- `C0.3` Список: карточки с превью, названием, статусом, счётчиком замечаний; превью соответствует содержимому.
- `C0.4` Пустое состояние списка (если можно воспроизвести): текст, кнопка действия.
- `C0.5` Длинное название макета не ломает карточку (проверь 80+ символов).
- `C0.6` Поиск/фильтр/сортировка в списке — есть? работают?
- `C0.7` Открытие макета: время до интерактивного листа (замер), отсутствие «мигания» превью.

### Z1. Создание, форматы, дублирование, удаление
- `C1.1` Создание макета: диалог, дефолтное название, валидация пустого имени.
- `C1.2` Все форматы: A4 портрет, A4 альбом, A3 портрет, A5, 1:1, 16:9 — лист и превью соответствуют пропорциям.
- `C1.3` A3: масштаб кеглей/полей сохраняет «оптический» размер (сравни с A4).
- `C1.4` 1:1 и 16:9: экспорт PDF даёт квадрат/16:9 без обрезки.
- `C1.5` Дублирование: копия полная, имя «— копия», оригинал не меняется.
- `C1.6` Удаление: подтверждение, поведение отмены, исчезновение из списка, товары каталога не тронуты.
- `C1.7` Смена формата у существующего макета: блоки не «улетают» за лист, предупреждение есть?
- `C1.8` Мастер/шаблоны при создании (если есть): что предлагает, применяется ли, можно ли пропустить.

### Z2. Каталог → лист
- `C2.1` Каталог виден, категории и позиции соответствуют реальному каталогу.
- `C2.2` Поиск по позиции: находит по части слова, регистронезависимо, с кириллицей и латиницей.
- `C2.3` Фильтр по категории; счётчики.
- `C2.4` Добавление позиции на лист: клик/двойной клик/drag — что работает, что нет.
- `C2.5` Добавление категории (заголовка группы).
- `C2.6` «Собрать из каталога»: раскладка в 2 колонки, порядок, ничего не теряется, отмена возможна.
- `C2.7` Позиция без фото: плейсхолдер осмысленный, не «битая картинка».
- `C2.8` Позиция без цены: предупреждение видно в редакторе, а не только при экспорте.
- `C2.9` Удалённая/скрытая в каталоге позиция: замечание в макете, что показывает блок.
- `C2.10` Позиция с объёмами/вариантами: как выводится «250 мл · 350 мл», помещается ли в блок.
- `C2.11` Очень длинное название позиции (искусственно длинное в тестовом товаре): перенос, обрезка, наложение.
- `C2.12` 50+ позиций из каталога: скорость, отзывчивость, нет ли фризов.

- `C3.4` Блок нельзя вытащить за лист; при попытке — прижимается.
- `C3.5` Точные координаты: поля X/Y/W/H в правой панели, шаг, единицы (% или мм), синхронизация с мышью.
- `C3.6` Сетка: включение/выключение, шаг, визуальная читаемость.
- `C3.7` Безопасная область/поля: видны, соответствуют PDF (сверь с экспортом).
- `C3.8` Привязки/направляющие при перетаскивании (snap к краям, к центру, к другим блокам) — есть? насколько «умные»?
- `C3.9` Выравнивание нескольких блоков, распределение по горизонтали/вертикали, «одинаковая ширина» — есть?
- `C3.10` Группировка/разгруппировка блоков — есть?
- `C3.11` Копирование/вставка/дублирование блока (`⌘C/⌘V/⌘D`), в т. ч. между страницами.
- `C3.12` Мультивыделение и общее перетаскивание группы.
- `C3.13` Зум: +/-, вписать лист, 100 %, зум колесом/жестом; зум не ломает координаты.
- `C3.14` Панорамирование (пробел+драг / средняя кнопка / скролл) при увеличенном масштабе.

- `C3.16` Поворот блока: поле/ручка в UI (в данных поворот заявлен) — доступен ли пользователю?
- `C3.17` Блоки с наложением: порядок отрисовки = порядок слоёв; перетаскивание поднимает наверх.

- `C3.19` Поведение при перетаскивании за пределы листа (отпускание мыши вне холста).

- `C5.18` Панель свойств на телефоне: доступна, не перекрывает лист, не теряет фокус.

### Z6. Оформление, тема, цвет — **главная зона для «10 из 10»**
Это место, где мы хотим быть не хуже Figma: **любой цвет, а не только зашитые варианты**. Проверяй придирчиво.

- `C6.1` Какие элементы вообще имеют настройку цвета? Составь полный перечень (фон листа, текст, акцент, линии, бейджи, заголовки категорий…).
- `C6.2` В каждом таком месте: можно ли ввести **произвольный HEX**? Проверь `#12AB34`, `#000000`, `#ffffff`, 3-значный `#abc`.
- `C6.3` Принимается ли **RGB/HSL** и альфа-канал (прозрачность)?
- `C6.4` Есть ли **пипетка** (Eyedropper) — взять цвет с фото/логотипа?
- `C6.5` Есть ли **цветовой круг/ползунки** или только поле ввода и свотчи?
- `C6.6` Палитра бренда: сколько цветов, можно ли добавить свой в палитру, сохраняется ли между макетами.
- `C6.7` Недавние цвета, «сохранённые палитры», палитры по шаблонам — есть?
- `C6.8` Градиенты (линейный/радиальный, 2+ стопа) — есть?
- `C6.9` Контраст: при выборе светлого текста на светлом фоне есть ли предупреждение; проверь контраст ключевых пар по WCAG (посчитай, не на глаз).
- `C6.10` Цвет применяется мгновенно и не «откатывается» после автосохранения.
- `C6.11` Цвет в PDF **совпадает** с экраном (сверь пипеткой по скриншоту PDF).
- `C6.12` Печать: предупреждение о цветах вне CMYK-гамута (есть? если нет — в план).
- `C6.13` Фон листа: цвет, картинка, затемнение 0–100 %, читаемость поверх.
- `C6.14` Тема: сколько тем, что меняют, можно ли смешивать темы и свои цвета.
- `C6.15` Шрифты: сколько доступно, есть ли кириллица у всех, что происходит при выборе шрифта без кириллицы.
- `C6.16` Можно ли загрузить свой шрифт (TTF/OTF/WOFF2) — есть? если нет, отметь как ключевой gap для «10/10».
- `C6.17` Орнаменты/декор/рамки: библиотека, масштабирование, цвет.
- `C6.18` «Сбросить оформление» / «вернуть как в шаблоне» — есть ли безопасный откат.
- `C6.19` Тёмная/светлая тема самой админки не ломает цвета макета.
- `C6.20` Проверка «дизайнерского» сценария: собери лист с нуля, используя **только** свою палитру из 3 произвольных цветов — сколько раз упёрся в ограничение? Опиши каждый случай.

### Z7. Сохранение, история, конфликты
- `C7.1` Автосохранение: индикатор меняется «Есть изменения → Сохранено», задержка ≤ ~1–2 с.
- `C7.2` Перезагрузка страницы сразу после правки — правка на месте.
- `C7.3` Закрытие вкладки сразу после правки — правка сохранена (flush).
- `C7.4` Потеря сети при правке: сообщение, повтор, отсутствие «тихой» потери данных.
- `C7.5` Две вкладки: конфликт обнаруживается, есть выбор «взять серверную / перезаписать»; данные не теряются молча.
- `C7.6` Undo/redo: глубина (проверь 20+ шагов), один шаг на жест, `⌘Z`/`⌘⇧Z`, кнопки в UI.
- `C7.7` Undo не отменяет чужие правки и не «съедает» автосохранение непредсказуемо.
- `C7.8` Undo после перезагрузки (ожидаемо — нет; отметь, понятно ли это пользователю).
- `C7.9` Статус «Не сохранено» при ошибке сервера: что видит пользователь, можно ли повторить.
- `C7.10` Горячие клавиши: стрелки, Shift+стрелки, Delete, Alt+Delete, `⌘Z`, `⌘⇧Z` — все работают и на русской раскладке.
- `C7.11` Горячие клавиши не срабатывают, когда фокус в поле ввода.
- `C7.12` Копирование/вставка из буфера между вкладками (если применимо).
- `C7.13` Долгая сессия (30+ минут, 100+ правок): нет деградации, нет утечки памяти (грубо — по отзывчивости).
- `C7.14` Уход со страницы с несохранёнными изменениями: предупреждение браузера/приложения.

### Z8. PDF и печать
- `C8.1` Экспорт `print`: файл скачивается, имя `menu-…pdf`, открывается в просмотрщике.
- `C8.2` Поля и метки реза присутствуют, bleed 3 мм; проверь линейкой по PDF (размер страницы в мм).
- `C8.3` Экспорт `screen`: без меток реза и bleed, размер совпадает с форматом.
- `C8.4` Соответствие холста и PDF 1:1: наложи скриншот редактора на страницу PDF — блоки не съезжают (допуск ≤ 1 мм).
- `C8.5` Векторный текст: при зуме 800 % текст не пикселизируется, шрифты не подменяются.
- `C8.6` Кириллица: все буквы, «ё», тире, кавычки-ёлочки, «₽» — без квадратов и подмен.
- `C8.7` Картинки: резкость, пропорции, `cover`/`contain`, прозрачность, webp/PNG/JPEG.
- `C8.8` Многостраничность: все страницы, правильный порядок, нумерация в подвале.
- `C8.9` Блокеры (позиция без цены / удалена из каталога): 409 → список → «Всё равно скачать» работает.
- `C8.10` Экспорт при 60+ блоках: время (замер), прогресс/спиннер, отсутствие таймаута.
- `C8.11` Экспорт с телефона: работает ли, понятна ли кнопка.
- `C8.12` Пустой лист: экспорт не падает, даёт осмысленный файл/сообщение.
- `C8.13` Скрытые блоки не попадают в PDF; удалённые с листа — тоже.
- `C8.14` Цвет фона/текста в PDF совпадает с экраном.
- `C8.15` Поворот блока (если доступен в данных/UI) корректно печатается.
- `C8.16` Печать из браузера (⌘P) не обязательна, но проверь, что не предлагается «печать страницы редактора» как основной путь.

### Z9. Мобильный редактор (<1024 px)
- `C9.1` Вкладки «Превью / Состав / Дизайн / PDF»: переключение, сохранение состояния.
- `C9.2` Выбор блока тапом; понятно, что выбрано.
- `C9.3` Правка X/Y/W/H полями: применяется, валидируется, не ломает вёрстку.
- `C9.4` Перетаскивание пальцем: работает, не скроллит страницу вместо перемещения.
- `C9.5` Resize на телефоне: есть? (если только поля — отметь как ограничение).
- `C9.6` Нижние панели не перекрывают лист и не «прилипают» к клавиатуре.
- `C9.7` Экспорт PDF на телефоне.
- `C9.8` Горизонтальная ориентация.
- `C9.9` Текст в полях не вызывает зум страницы (iOS), шрифт ≥16 px.
- `C9.10` Реальный смартфон, если есть доступ (не только эмуляция): drag/тап/скролл.

### Z10. UX, доступность, производительность, ошибки
- `C10.1` Понятность без обучения: за 60 секунд новый пользователь (сыграй роль) находит «добавить позицию», «поменять цвет», «экспорт».
- `C10.2` Пустые состояния: пустой лист, пустой каталог, пустая страница — есть подсказка.
- `C10.3` Микрокопия: тексты кнопок/ошибок по-русски, без техножаргона, с действием.
- `C10.4` Ошибки: сообщение + что делать; нет «Error 500» без контекста.
- `C10.5` Деструктивные действия: подтверждение, «Отменить» в тосте.
- `C10.6` Загрузка: скелетоны/спиннеры, нет «прыжков» контента.
- `C10.7` Клавиатурная доступность: Tab-порядок, фокус-обводка, `Escape`, работа без мыши на 100 % (список недоступного).
- `C10.8` Скринридер (кратко): есть `aria-label` у иконочных кнопок, лист не «немой».
- `C10.9` Контраст интерфейса (не макета): кнопки, подписи, disabled — по WCAG AA.
- `C10.10` Производительность: замер TTI редактора, отзывчивость drag при 60–100 блоках (субъективно + Performance-панель: длинные задачи, FPS).
- `C10.11` Память/нагрузка: после 30 минут работы интерфейс не «тормозит».
- `C10.12` Консоль: нет ошибок в нормальном сценарии; перечисли все, что появились (с шагами).
- `C10.13` Локализация дат/чисел/цен: `₽`, пробелы‑разделители, «169 ₽» против «169,00 ₽».
- `C10.14` Настройки редактора (если есть) сохраняются между сессиями.
- `C10.15` Внешний вид админки консистентен: кнопки/инпуты/тосты в одном стиле.

## 7. Часть C. План развития до «10 из 10»

Требования к плану:

1. **Фазы:** `P0` — довести до «не стыдно показывать дизайнеру» (1–2 недели), `P1` — уровень Canva (3–6 недель), `P2` — уровень Figma по ключевым для нас вещам (1–2 месяца), `P3` — дифференциация (наше преимущество).
2. **Формат задачи:** `ID | Фаза | Задача | Проблема (боль) | Решение | Библиотека/техника | Оценка (дни) | Зависимости | Критерий приёмки (проверяемый) | Риск`.
3. **Критерий приёмки — проверяемый в браузере**, не «улучшить UX». Пример: «в панели «Оформление» любое поле цвета принимает HEX/RGB/HSL, поддерживает alpha с шахматкой, пипетку; контраст < 4.5 подсвечивается; значение сохраняется после перезагрузки и совпадает в PDF».
4. **Минимум 60 задач**, из них ≥ 15 «quick wins» ≤ 1 дня, сгруппированных отдельным списком (их делаем первыми).
5. **Приоритизация по влиянию:** impact (1–5) × confidence (1–5) / effort. Покажи таблицу приоритетов.
6. **Метрики успеха:** время «с нуля до готового PDF» (цель: ≤ 15 минут), число кликов на типовую операцию, число блокеров на экспорте, доля макетов без замечаний, FPS при 100 блоках, TTI редактора, число обращений в поддержку (если известно), NPS владельца (если применимо).
7. **Риски и техдолг:** что сломается при росте (монолит редактора, проценты vs мм, отсутствие группировки, PDF на сервере, шрифты только 2 семейства), и как это разложить по фазам.

### 7.1. Обязательные темы в плане

**Цвет и стиль (ядро запроса):** произвольный цвет везде, alpha, пипетка, HEX/RGB/HSL, палитры бренда и «свои», сохранение палитры между макетами, недавние, градиенты, контраст-чек, предупреждение о CMYK, «вернуть как в шаблоне», дизайн-токены (акцент/фон/текст/линия), глобальная смена акцента одним действием.

**Типографика:** ≥ 10 шрифтов с кириллицей, пары «заголовок/текст», загрузка своего шрифта, веса, трекинг, интерлиньяж, капс, авто-фит текста в блок, переносы, висячая пунктуация, стили (H1/цена/описание) вместо ручных настроек.

**Компоновка:** сетки и модули, авто-layout (колонки), привязки и направляющие, линейки, выравнивание/распределение, группы, блокировка, мультивыделение, копирование стиля, «умная» замена позиции с сохранением рамки.

**Данные:** смена цен без слома вёрстки, «обновить с каталога» с предпросмотром diff, объёмы/варианты, стоп-лист, сезонные категории, бейджи, QR на меню, ссылка на предзаказ, дата актуальности цен в подвале.

**Печать:** bleed/метки реза/безопасные поля, предупреждения о разрешении фото (< 200–300 dpi), CMYK-профиль или честное «RGB → типография», пресеты типографий (A3 2 фальца, A4 евробуклет), спуск полос, проверка «текст не меньше 7 pt», «контраст», «фото не растянуто».

**Удобство:** палитра команд, контекстное меню, инспектор без «прыжков», панель слоёв с деревом, шаблоны под форматы, онбординг «3 шага», пустые состояния, отмена в тосте, сохранение зума/позиции, режим презентации, «показать, как будет в печати».

**Надёжность:** версии/история, автосейв-индикатор, восстановление после сбоя, конфликты вкладок, экспорт в фоне, лимиты размера, обработка ошибок.

**Совместная работа (P2–P3):** комментарии к блокам, ссылка на просмотр, роли, совместное редактирование (осторожно с оценкой), шаблоны от бренда.

**Мобайл:** правка на телефоне «на бегу»: превью, быстрые правки (цена/фото/скрыть), полноценный редактор — на планшете.

### 7.2. Определение «10 из 10» (рубрика)

Дай таблицу из 10 критериев, каждый 0–10, с обоснованием и доказательством, и целевую формулировку. Базовая рубрика (можно уточнить):

1. Цвет и оформление без ограничений.
2. Типографика.
3. Компоновка и точность (снапы, выравнивание, группы).
4. Работа с данными каталога и ценами.
5. Экспорт и печать.
6. Скорость типового сценария (время/клики).
7. Надёжность и сохранность.
8. Мобильный опыт.
9. Доступность и понятность.
10. Визуальное качество результата (можно ли сделать «красиво», а не только «правильно»).

Итог: сумма, вывод «сколько сейчас / сколько будет после P0 / P1».

## 8. Структура итогового отчёта

Один файл `MENU-EDITOR-AUDIT-<YYYY-MM-DD>.md` + папка `screenshots/` (имена `NN-зона-что.png`). Порядок разделов:

1. **Резюме для владельца** (≤ 1 страница): что работает, что нет, 5 главных проблем, 5 главных быстрых побед, текущая оценка X/10 и что даст P0.
2. **Методика и окружение**: браузеры, разрешения, дата/время, созданные `QA-` объекты, что удалено.
3. **Сводная таблица результатов** по зонам Z0–Z10: `OK / PARTIAL / FAIL / NOT TESTED`, количество, доля.
4. **Список дефектов**: `ID | Severity | Зона | Что | Шаги | Ожидание | Факт | Доказательство | Воспроизводимость`.
5. **Подробный чек-лист** (все пункты с фактическим результатом).
6. **Мобильный опыт** отдельным разделом (скриншоты 390×844).
7. **PDF и печать**: скриншоты PDF, замеры, наложение на холст.
8. **Сравнение с Figma / Canva / Adobe Express / (2 других)**: матрица + сценарии S1–S8 с временем и кликами.
9. **«Как у них» → «как у нас»**: 10–15 разрывов с визуальными примерами.
10. **Библиотеки**: таблица кандидатов, вердикты, ссылки, лицензии; 3–5 архитектурных развилок с рекомендацией.
11. **План развития**: P0–P3, ≥ 60 задач таблицей, quick wins, приоритеты, метрики, риски.
12. **Рубрика 10/10** и целевое состояние.
13. **Что не проверено и почему** (блокеры доступа, отсутствие данных, ограничения браузера).
14. **Приложение**: индекс скриншотов, журнал изменений данных, ссылки на источники.

### Требования к качеству отчёта

- ≥ 100 проверенных пунктов, ≥ 40 скриншотов, ≥ 60 задач в плане, ≥ 12 библиотек в таблице.
- Каждое утверждение проверяемо: либо скриншот, либо шаги. Никаких «вероятно», «скорее всего».
- Пиши как продуктовый аналитик для владельца бизнеса и для команды разработки одновременно: сначала вывод и влияние, потом детали.
- Не сглаживай. Если что-то плохо — скажи прямо, с доказательством и предложением.
- Если находишь проблему, которой нет в чек-листе, — добавь со своим ID (`X1`, `X2`…) и severity.

## 9. Что считается «заданием не выполнено»

- Отчёт без сравнения с Figma/Canva/Adobe Express (или сделанный «по памяти», без скриншотов).
- Отчёт без списка библиотек с лицензиями и ссылками.
- План без оценок, зависимостей и проверяемых критериев приёмки.
- Утверждения «не работает» без шагов и скриншота.
- Изменённые реальные данные без записи в журнале и без восстановления.
- Токен/персональные данные в отчёте или на скриншотах.
