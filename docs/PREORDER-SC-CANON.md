# Канон `sc` в чеке Эвотора (льготы предзаказа)

Что backend ожидает от кассы в `extras.sc` (JSON в чеке).

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `sc.v` | number ≥ 2 | да | версия конверта |
| `sc.c` | string | да | подписанный токен карты (с точкой) или числовой код карты |
| `sc.free` | 0/1 | нет | касса просит списать подарок |
| `sc.cb` | копейки | нет | касса просит списать кэшбэк |
| `sc.voucherId` | id | нет | ваучер, который применяют |
| `sc.ts` | number | нет | метка времени кассы |
| **`sc.preorder`** | uuid | да, если чек закрывает предзаказ | **id предзаказа** — канон для льгот |
| `sc.ord` | string | нет | id **очереди** (`queue_numbers`), не заказ |
| `sc.qn` | string | нет | публичный номер заказа (только для логов) |
| `sc.op` | string | нет | id резерва лояльности (для чеков без заказа) |

## Правила (P0-3)

1. Льгота предзаказа (подарок/кэшбэк/ваучер из заказа) применяется **только** по `sc.preorder`.
2. `sc.ord` — номер очереди. Он **не** считается заказом: короткие значения (`42`, `111111`)
   игнорируются, иначе можно списать чужой бонус.
3. Переходный период: если `sc.ord` содержит uuid **и** такой заказ существует, он принимается
   как заказ, но в лог пишется `sc.ord with preorder id: legacy field` — так помечаем старые сборки APK.
4. Неизвестный `sc.preorder` → льгот нет + запись в лог; ничего не списываем.
5. Списание резерва возможно только для подписанной карты (`sc.c` с точкой — token-путь);
   для числового кода касса применяет скидку сама, сервер только фиксирует продажу.

## Что должен делать APK-агент

- писать `sc.preorder = <order id>` при закрытии предзаказа;
- не класть id заказа в `sc.ord` (там только id очереди);
- для льгот по заказу использовать подписанный токен карты, а не числовой код.
