# Макет меню — AI-помощник (этап 5)

Продолжение [AUDIT-MENU-LAYOUT-STAGE4-6-SLICE.md](./AUDIT-MENU-LAYOUT-STAGE4-6-SLICE.md).
Сделано главное правило аудита: **AI предлагает операции, применяет владелец**.

## Как работает

`backend/src/modules/admin/menuLayoutAi.ts`:

1. **`propose`** превращает фразу в список операций над секциями — и ничего не пишет в документ.
   Понимает: «добавь напитки» (добавит только отсутствующие позиции категории), «убери корицу»
   (скрыть, не удалить), «переименуй добавки в топпинги».
2. **`applyOps`** — чистая функция: применяет `add-section / add-items / hide-item / remove-item /
   rename-section / reorder-items` к документу.
3. **`POST /menu-layouts/:id/ai/apply`** — применяет, пересобирает лист движком и сохраняет.
   `baseRev` защищает от затирания чужих правок (409).

Без ключа AI работает разбор по правилам — функцию можно тестировать и показывать без внешнего провайдера.
Ключ понадобится, когда добавим свободные формулировки.

## Интерфейс

Строка AI в редакторе (при `VITE_MENU_LAYOUT_V2=1`): поле запроса → «Предложить» → строка
«summary · операций N. Запишем только после подтверждения» → «Применить» / «Отмена».

## Проверки

| Что | Результат |
|---|---|
| `npm run typecheck` | 3/3 |
| backend | **801** тест (+5: предложение, скрытие, переименование, применение через API, 409) |
| `npm run build` | OK |

Отдельно проверено: «добавь напитки» предлагает **только отсутствующие** позиции; непонятная фраза
не предлагает ничего; `/ai/apply` с устаревшим `baseRev` даёт 409.

По ходу поймал классическую ловушку с кириллицей: `\b` и `\w` в JS работают только с ASCII, поэтому
«убери корицу» и «переименуй…» сначала не распознавались — заменил на явные классы и сравнение по корню.
