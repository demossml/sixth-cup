## Задача 1.1 — одна геометрия листа (ML-01, ML-11)

**Было.** Холст позиционировал блоки от **края листа**: абсолютные `%` считаются от padding box, а padding
`.mc-sheet` (4,4 % / 6 %) на них не влиял. PDF ставил блоки по формуле `pad + x% * cbW` с симметричным `pad = 26 pt`.
Итог: превью ≠ печать, текст мог уехать на обрез, а поля сверху/снизу в CSS и PDF имели разную высоту.

**Стало.** Одно правило в двух зеркальных модулях:

```ts
// backend/src/modules/admin/sheetGeometry.ts
export const SHEET_SAFE = { x: 0.044, top: 0.044, bottom: 0.06 }  // доли ШИРИНЫ листа
contentBox(width, height, bleed)   // → { x, y, w, h } в pt
placeBlock(box, block)             // xPct/yPct/wPct/hPct → pt
footerBaselineY(height, width, bleed)
```

```ts
// frontend-admin/src/lib/sheetGeometry.ts — те же числа
SHEET_SAFE = { x: 4.4, top: 4.4, bottom: 6 }   // проценты ширины
safeAreaStyle                                   // left/right/top/bottom в cqw
safeBoxSize(rect)                               // размер безопасной области для жестов
ptToWidthPct(pt)                                // 1 pt = 0.168 % ширины листа
```

Изменения:

1. `MenuCanvas` рендерит блоки внутри `.mc-safe` — абсолютной рамки с отступами `4.4cqw / 4.4cqw / 6cqw`.
   `cqw` — это ровно 1 % ширины листа (у `.mc-sheet` стоит `container-type: inline-size`), поэтому проценты
   в `doc_json` теперь означают одно и то же на экране и в PDF.
2. PDF читает `contentBox` / `placeBlock` / `footerBaselineY` — никаких собственных `pad` и `cbW` больше нет.
   Поля сверху и снизу теперь тоже измеряются в долях ширины, как в CSS (раньше были 26 pt со всех сторон).
3. Подвал листа `footerBaselineY` = 62 % нижнего поля — та же доля, что `bottom` у `.mc-foot`.
4. Перетаскивание считает проценты от **безопасной области** (`safeBoxSize`), поэтому «протащил 51 px» на листе
   560 px даёт ровно 9,99 % (проверено в браузере: `xPct` стал 9.99).
5. Сетка и рамка безопасной области в редакторе (`is-grid` / `is-safe`) выставлены по тем же `cqw`.
6. Кегль: `ptToCqw` больше не зажимается минимумом 1,6 cqw — превью показывает тот же кегль, что напечатается
   (1 pt = 0.168 % ширины листа для любого формата, потому что в PDF кегль масштабируется вместе с листом).
   Кегль 10 pt на A4 — это 1,68 % ширины и на A3 тоже, так что ML-11 закрывается этим же правилом.
7. Ручка ресайза: `max(12px, 1.5cqw)` вместо жёстких 1,5 cqw — на телефоне было 5,4 px. Полный тач-режим
   (ML-02, зона касания 44 px, pinch-zoom) остаётся на задачу 1.7.

## Задача 1.2 — история: один жест = один шаг (ML-03)

Вынесено в чистый модуль `frontend-admin/src/lib/docHistory.ts`: `pushHistory`, `undoStep`, `redoStep`,
`canUndo`/`canRedo`, лимит **100** шагов (было 12). Хранится в state, поэтому кнопки обновляются сразу.

- Перетаскивание и ресайз двигают документ десятки раз за жест, но снимок в историю попадает **один** —
  на первом `pointermove`; остальные кадры идут без истории (`drag.pushed`).
- Появился **redo**: кнопка «Вернуть», `⌘Z` / `Ctrl+Z` — отмена, `⌘⇧Z` / `Ctrl+Y` — возврат.
- Новая правка обнуляет redo; при загрузке макета и после seed/sync/freeze история сбрасывается.

Проверено в браузере: drag из 8 движений → `xPct` 0 → 12,53 → одна «Отменить» вернула 0, «Вернуть» стало активным.

## Задача 1.3 — очередь сохранения (ML-04)

- Таймер автосохранения живёт в `saveTimer`, актуальный payload — в `pending`/`latest`.
- `flush()` досылает несохранённое **перед** `seed-from-catalog`, `sync-prices` и сменой режима цен:
  раньше сервер возвращал документ и молча перезаписывал локальные правки.
- `pagehide` + `visibilitychange` → `fetch(..., { keepalive: true })`: правки последних 0,8 с не теряются
  при закрытии вкладки.
- Счётчик версий `saveSeq`: ответ устаревшего PUT не перебивает статус и `savedAt` более нового.

## Задача 1.4 — версии и конфликты (ML-05)

- Миграция `058_menu_layout_rev.sql`: `menu_layouts.rev INTEGER NOT NULL DEFAULT 1`
  (rollback обнуляет версию — SQLite не умеет `DROP COLUMN`).
- `PUT` принимает `baseRev`; при расхождении — `409 { error: 'rev_conflict', rev, layout }`.
  Без `baseRev` (старые клиенты) сохранение разрешено, но `rev` всё равно растёт.
- Клиент отправляет `baseRev` каждый раз и обновляет `rev` из ответа.
- На 409 показывается баннер: **«Взять серверную»** (перечитывает макет) или
  **«Перезаписать своей»** (берёт актуальный `rev` и сохраняет локальную версию). Автосохранение на это время
  приостановлено, чтобы не спамить 409.
- `rev` есть в ответе списка и карточки макета.

Проверено в браузере: правка «из другого окна» через API → в редакторе баннер → «Перезаписать своей» →
`rev` 7 → 8, статус «сохранено только что».

## Задача 1.5 — картинки только из uploads (ML-07)

- `normalizeBlock` хранит `url`/`photoUrlOverride` только если это `/uploads/<файл>`; внешние ссылки
  отбрасываются при чтении **и** при записи.
- zod `uploadUrlZ` (`^/uploads/[A-Za-z0-9._-]+$`) — новый клиент с внешней ссылкой получает 400.
- Резолв проверяет файл на диске: если его нет — предупреждение «файл картинки не найден», код блокера
  **`image_unreadable`**; для внешней ссылки (может прийти из старого каталога) — «внешняя ссылка на фото
  не печатается».
- В редакторе поле ссылки принимает только `/uploads/…`, иначе тост «Только файл из админки».

## Задача 1.6 — удаление блока (ML-08)

- `Delete`/`Backspace` теперь **удаляет** блок с листа (раньше только скрывал); `Alt+Delete` — скрыть.
- Кнопка «Удалить блок» в панели свойств и корзина в каждой строке панели «Слои» (доступно и с телефона).
- Удаление — обычная правка документа, поэтому отменяется `⌘Z`; товар каталога не затрагивается.

## Задача 1.7 — тач (ML-02, ML-14): частично

- Ручка ресайза: визуально `max(12px, 1.5cqw)` (было 5,4 px на телефоне), зона касания 44 px через
  псевдоэлемент `::after`.
- `touch-action: pan-x pan-y` у блока до выделения — палец листает страницу; у выделенного блока
  `touch-action: none` — палец двигает блок. В подсказке редактора: «На телефоне сначала коснитесь блока».
- **Не сделано:** pinch-zoom и полный мобильный режим «список секций + нижний лист» (это отдельный L-объём,
  этапы 2–3).
