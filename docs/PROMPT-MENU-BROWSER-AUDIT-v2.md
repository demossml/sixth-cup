2. **Свои запросы к API запрещены.** Нельзя `curl`, `fetch`, `XMLHttpRequest`, Postman. Разрешено **наблюдать** network-панель при действии в интерфейсе (URL, метод, статус, ключи ответа) — это доказательство поведения UI, а не обход UI.

Нужны особые данные (товар без цены, скрытый товар, позиция с объёмами) — ищи их среди существующих, а не создавай. Если таких нет — фиксируй как «не проверено: нет данных» с указанием, какие данные нужны.
4. **Разрешено менять только макеты** и только `QA-`-префиксом; удалять за собой. Прод-макет id=1 «ВЕСНА/ЛЕТО 2026» — не трогать (только чтение).
5. **Скриншоты больше не требуются.** Требование ≥ 40 скриншотов из v1 снимается: у тебя нет визуального канала. Вместо них — **протокол в текстовом виде** (раздел 2) и **список «должен проверить человек»** (раздел 6.2). Никаких «скриншот приложен» без файла — это уже было в round 1.
6. **Никаких утверждений без числа или текста из интерфейса.** «Похоже», «вероятно», «должно быть» — запрещены. Формат: «нажал X → увидел Y → ожидал Z».

## 2. Как доказывать без скриншотов

Каждый проверенный пункт — строка с полями:

`ID | Статус (OK/PARTIAL/FAIL/BLOCKED) | Путь в UI | Действие | Наблюдение (текст/число/ошибка) | Ожидание | Вывод`

**Разрешённые измерения в devtools** (это и есть твой «глаз»):

| Что нужно | Чем мерить |
|---|---|
| Включён ли ввод HEX текстом | попробовать вписать `#12AB34` в поле и нажать Enter; зафиксировать, появилось ли значение и изменился ли цвет (`getComputedStyle(el).backgroundColor`) |
| Позиция/размер блока | `el.getBoundingClientRect()` до и после drag; перевести в % от листа |
| Реальный цвет элемента | `getComputedStyle(el).color / .backgroundColor` (даёт `rgb(…)` — привести к HEX) |
| Контраст | посчитать по WCAG из двух `rgb(…)`; привести числа и вердикт (≥ 4.5 / ≥ 3 для крупного) |
| Минимальный размер блока | уменьшать перетаскиванием до отказа, зафиксировать `rect.width/height` |
| Сохранение | network: `PUT/POST` по макету — статус, тело запроса (ключи, не токен), время |
| Конфликт вкладок | вторая вкладка → правка → статус ответа и текст диалога |
| Ошибки | console: полный текст ошибки + стек-топ-строка (1 строка) |
| Производительность | Performance-панель: длительность задачи при drag, FPS-график — числа, не «тормозит» |
| PDF | страница в просмотрщике: кол-во страниц, размер страницы, текст (через поиск), шрифты (свойства документа) |
| Мобильный | эмуляция 390×844 + тач: что именно не срабатывает, в какой момент |

**Итог:** каждое «не работает» должно воспроизводиться по описанию без картинки. Если проверка принципиально требует глаз (красиво/некрасиво, «съехало визуально») — она идёт в «должен проверить человек», а не в OK/FAIL.

## 4. Обязательный артефакт № 2: исправления двух ложных выводов

### 4.1. `B7` «Точечное добавление дублирует товар» — снять или доказать заново

Факты, которые владелец проверил вне аудита:

- В **прод-бандле** редактора присутствует строка «уже на листе — выделил блок» и кнопка «Убрать дубли».
- В текущей сборке (`main`, коммит `7ef2c49` от 10.11.2026 11:44) повторное добавление товара выделяет существующий блок и не создаёт новый.

Что сделать: воспроизвести **на проде в новой вкладке с очищенным кешем** (hard reload) и зафиксировать: клик по карточке уже добавленного товара → что произошло (тост? выделение? сколько блоков было/стало? какой `productId`?). Если дефекта нет — статус `NOT A DEFECT` с доказательством. Если воспроизводится — указать точный сценарий, в котором он есть (назови продукт, страницу, режим «Места»/«Лист»).

### 4.2. `DUP` «Товар с объёмами разбит на 3 блока» — переписать диагноз

Каталог прода хранит объёмы **отдельными товарами**: `Капучино 250 мл`, `350 мл`, `400 мл` — три разных `product_id` с общим `groupId`, признаком «есть объёмы» и «цена от». То же с `Американо 250/350/400 мл`. Значит:

- дедуп по `productId` работает правильно: 3 разных товара → 3 блока;
- проблема не в дедупе, а в том, что раскладка **не собирает группу объёмов в один блок** «250 · 350 · 400» (при том, что на карточке каталога объёмы уже показываются строкой).

Что сделать:

1. Проверить в UI, что каталог показывает товары по одному на объём и/или группирует их визуально (зафиксировать, как именно выглядит список).
2. Проверить, что «Собрать из каталога» кладёт по блоку на каждый объём (сколько блоков на «Капучино», сколько на «Американо»).
3. Сформулировать корректную задачу: «агрегировать группу объёмов в один блок при раскладке и при точечном добавлении; печатать `250 · 350 · 400` с ценами под объёмами». Severity — по влиянию на печать (это S2, не S1: данные не теряются, лист просто длиннее).
4. Отдельно проверить сценарий «в каталоге 3 товара, а нужно 1 блок» — есть ли ручной способ получить один блок (например, блок категории/текста) и насколько это неудобно.

### 4.3. `D18` «Слои показывают “Позиция”» — уточнить причину

Имя слоя берётся как: `displayName` из ответа сервера → иначе название из каталога по `productId` → иначе «Позиция». То есть «Позиция» — не отсутствие фичи, а отсутствие резолва.

Что сделать: на проде открыть макет, где у блоков точно есть названия, и зафиксировать **по каждому типу блока** (позиция, категория, текст, картинка, логотип, разделитель), что показывает панель слоёв и заголовок свойств. Если имена есть — снять дефект. Если нет — указать, для каких блоков и в каком месте (список слоёв / заголовок свойств / оба).

## 5. Обязательный артефакт № 3: глубокий цвет (ядро «10 из 10»)

Цвет — главный разрыв, и в round 1 он раскрыт на 1 строку («3 нативных input»). Нужен разбор по каждому месту настройки цвета. Сначала составь **перечень всех мест**, где вообще можно задать цвет (тема: фон листа, текст, акцент; бейджи; линии/разделители; заголовки категорий; фон карточки; цвет ссылок/QR; фон страницы и т. п.).

По каждому месту заполни:

| Проверка | Как доказать |
|---|---|
| Ввод HEX текстом | вписать `#12AB34` и `#abc`, Enter → изменился ли цвет (`getComputedStyle`) |
| RGB / HSL | есть ли переключатель формата или поля |
| Alpha / прозрачность | есть ли слайдер/8-значный HEX; что происходит при вводе `#00000080` |
| Пипетка | есть ли кнопка; при клике — открывается системный EyeDropper? |
| Палитра бренда | сколько свотчей; применяются ли ко всем трём полям или только к акценту |
| Своя палитра | можно ли сохранить свой цвет «в бренд»; переживает ли перезагрузку и другой макет |
| Недавние цвета | есть ли |
| Градиенты | есть ли (линейный/радиальный, число стопов) |
| Цветовой круг/ползунки | что именно открывает нативный пикер (это ОС, а не продукт — зафиксируй отдельно) |
| Контраст | для 3 пар (текст/фон, акцент/фон, бейдж/фон) посчитать WCAG; предупреждает ли UI |
| Сброс к теме | есть ли «вернуть как в шаблоне» |
| Сохранение | после перезагрузки и повторного входа значения те же |
| Совпадение с PDF | смотри 4.4 ниже |

**4.4. Цвет в PDF.** Прямое сравнение «пипеткой по PDF» в браузере недоступно (страница PDF — не DOM). Сделай так:

1. Задай в теме заведомо отличимые цвета: фон `#12AB34`, текст `#AB1234`, акцент `#1234AB`.
2. Экспортируй `print` и `screen`.
3. В просмотрщике проверь, что изменились (визуально — если канал есть; иначе статус `BLOCKED: нужен человек`) и **обязательно** проверь косвенно: размер файла, наличие векторного текста, отсутствие растровой подмены (по свойствам документа).
4. Все пункты, где нужен глаз, — в раздел 6.2, а не «OK».

**Вывод по цвету:** одна таблица «место × возможность» (HEX/RGB/HSL/alpha/пипетка/палитра/градиент/контраст) со статусами и одна сводная оценка «сколько из 8 возможностей есть хотя бы в одном месте и сколько — во всех».

## 6. Обязательный артефакт № 4: рынок и «что должен проверить человек»

### 6.1. Figma / Canva / Adobe Express — честный формат

Живой замер сценариев S1–S8 в round 1 не выполнен (и без визуального канала не выполним). Поэтому:

- Каждое утверждение о чужом продукте — **со ссылкой на первоисточник** (help-центр, release notes) и датой.
- Для каждой возможности в матрице укажи уровень доказательства: `документация` / `публичное демо` / `живой аккаунт` (последний, скорее всего, недоступен — так и напиши).
- **Не пиши «у них есть», если это следует только из обзоров третьих лиц.** Тогда — `по обзорам, не подтверждено`.
- Сценарии S1–S8 оформи как «требуется живой замер человеком»: таблица «сценарий → что мерить → какой инструмент у нас блокирует» — это уже польза, даже без цифр.

### 6.2. Список «должен проверить человек»

Итоговый раздел: всё, что нельзя закрыть в текстовой среде, одним списком с форматом `что проверить | где | как | почему агент не может`. Ожидаемо: визуальное совпадение холста и PDF, читаемость вёрстки, «красиво/нет», цвет в PDF, реальный смартфон, скринридер. Этот раздел — не отписка, а рабочее задание для владельца/дизайнера.
