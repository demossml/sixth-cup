# Разрыв: наше меню vs эталон `index (4).zip` (Cobalt Counter)

Дата: 07.11.2026. Сравнение вживую: эталон `menu-prototype/` из архива против текущего PWA
(`frontend`, ветка `main`, коммит `969f4a9`).

> **Статус: реализовано 07.11.2026** поверх коммита `969f4a9`. Разделы 1–7 описывают исходный разрыв
> (что было не так), раздел 10 — что сделано и что осталось. Палитра — **наша** (`white/ice`,
> `#0B4A8D`): решение владельца «палитра бренда, композиция и поведение 1:1».

Как воспроизвести:
```bash
# эталон
cd <распакованный index (4)>
python3 -m http.server 8098          # http://127.0.0.1:8098/index.html
# наше приложение (backend отдаёт собранный PWA)
cd backend && DB_PATH=./data/sixth-cup.db NODE_ENV=production PORT=3975 node dist/index.js
# http://127.0.0.1:3975/menu
```

## 1. Главное: это два разных эталона

| Что | Эталон `index (4)` (Cobalt Counter) | Наше приложение |
|---|---|---|
| Титульный экран | «Карта»: штампы **3 из 5**, «Ещё 2 стакана до подарка», кэшбэк `4,50 ₽`, QR карты, «В меню / История» | Титул по `TITLE-SCREEN-PWA-SPEC`: стикеры **0…5** на ассете, промо «6-й стакан», карта-пропуск 112 px, приглашение друга, код восстановления |
| Меню | photo-first: hero «Сезон», «Популярное», «Смотреть всё», карточки 4:5 | плоская сетка всех товаров с чипами категорий |
| Карточка товара | отдельный **экран**: КБЖУ, объём, молоко, добавки, sticky CTA с суммой | **bottom sheet**: фото, имя, цена, ккал, «В корзину» |
| Корзина | отдельный **экран**: «Где заберёте · Изменить», «Скидки и бонусы», «Изменить/Удалить», «Отправить в кофейню» | **bottom sheet**: селект точки, ± количество, «Собрать заказ» |
| Палитра | `--brand #002FA7`, `--paper #F6F3EE`, `--ink #1B1A17`, `--line #E7E1D6` (крем) | `#0B4A8D`, `#FFFFFF`, `#D9E6F5` (white/ice) — по правилу бренда от 06.11 |

То есть меню сейчас сделано по **упрощённой** спека-версии, а не по `index (4)`.
В [`PREORDER-ROLLOUT-PLAN.md`](./PREORDER-ROLLOUT-PLAN.md) это было зафиксировано как P2-3 «Меню 1:1» и
сознательно не входило в этапы A–G. Плюс палитра: правило бренда прямо запрещало крем `#F6F3EE` и
`#002FA7`, которые использует этот эталон.

## 6. Что уже соответствует или лучше эталона

- Статусы заказа: эталон мокает (`sent → accepted → preparing → ready → paid`), у нас **реальный бэкенд**
  с ETA, авто-переходами, баном за невыкуп и админ-страницей — это не регресс, это плюс.
- QR заказа, «это не карта лояльности», оплата на кассе — совпадает.
- Нижняя навигация, «Ещё» (профиль, история, приглашение, акции, кофейни, about, legal) — совпадает по составу.
- Шрифты: в обоих Unbounded + Golos Text — совпадает.
- Офлайн-кэш меню и «нет сети» — совпадает.

## 7. Чего не хватает в данных

| Нужно эталону | Что есть | Что делать |
|---|---|---|
| КБЖУ (белки/жиры/углеводы) | `products.calories` только ккал | миграция: `protein_g`, `fat_g`, `carbs_g` + поля в админке |
| Фото 4:5 товаров | `products.image_url` есть, фото не загружены | загрузить в админке (инфраструктура есть) |
| Объёмы с ценой | два механизма: группы-варианты (`product_groups`) и `volume_schemes` + `product_volume_prices` | решить один источник; для меню нужен гостевой конфиг |
| Молоко с доплатой | `milk_schemes` + `milk_scheme_variants` (есть `is_free`, `is_default`) | отдать в гостевой API |
| Добавки по желанию (radio + степпер до N) | `modifiers` + `modifier_schemes` (`required`, `max_count`) | отдать в гостевой API |
| Бейджи «Хит»/«Сезон» | `promos.badge` (CMS) | уже поддержано, нужен контент |
| Часы и координаты точек | в `stores` нет | миграция + поля в админке |

**Ключевой технический пробел:** нет гостевого эндпоинта конфигурации товара
(`GET /api/preorder/config/:productId?storeId=`) — это P1-1 из плана. Без него карточка с молоком и
добавками не собирается; в заказ уходят только `productId + quantity` (и объём, если заведён группой).

## 8. Предлагаемая серия этапов (чтобы стало 1:1)

| Этап | Что делаем | Критерий GREEN |
|---|---|---|
| **M-1** | Гостевой конфиг товара: объёмы (цены), молоко (доплата, default, стоп), добавки (обязательные/по желанию, maxCount), choice-схемы, sold-out | ответ API = тому, что рисует эталон; тесты |
| **M-2** | Экран карточки товара (вместо sheet): фото 4:5, КБЖУ, объём, молоко, добавки, live-цена, sticky CTA с суммой и кол-вом | сценарий «300 мл + кокос + корица + ваниль = 370 ₽» |
| **M-3** | Экран меню: шапка с лого+поиск, строка точки, счётчик позиций, hero «Сезон», «Популярное» + «Смотреть всё», карточки 4:5, «от N ₽» | пиксельное сравнение с эталоном по блокам |
| **M-4** | Экран корзины: адрес + «Где заберёте», шаг «Скидки и бонусы», состав позиции, «Изменить/Удалить», «Позиции/Итого», «Отправить в кофейню» + «Добавить ещё»; состав параметров в заказе (уже поддерживается `modifiers`) | заказ с модификаторами доезжает до кассы |
| **M-5** | Выбор кофейни первым экраном (карта-схема, часы, «Открыто/Закрыто», гео) + миграция `stores.hours/coords` | без выбора точки меню не открывается |
| **M-6** | КБЖУ: миграция `protein_g/fat_g/carbs_g`, поля в админке, плитки в карточке; загрузка фото 4:5 | плитки заполняются из админки |

Порядок и правила те же, что в предзаказе: один этап = один прогон, без регресса, отчёт по этапу.

## 9. Блокирующее решение владельца

**Палитра.** Эталон кремовый (`#F6F3EE` + `#002FA7`), текущий бренд-гайд — white/ice (`#FFFFFF` + `#0B4A8D`).
Раньше было зафиксировано «крем и `#002FA7` не возвращаем». Варианты:

- **A. Палитра эталона** — меню и карточки становятся кремовыми, как в `index (4)`; тогда титул и админка
  визуально выпадают, нужен отдельный этап перекраски всего приложения.
- **B. Наша палитра, композиция эталона** — повторяем структуру, блоки, размеры, поведение 1:1,
  но на white/ice `#0B4A8D`. Меню остаётся в едином стиле с титулом.

### 10.2 Карточка товара (`/menu/:productId`)

Полноэкранный экран: фото 4:5 с бейджем, название + живая цена, описание, плитки КБЖУ,
«Объём» (с ценами, метка «обязательно»), «Молоко» (с доплатой, метка «обязательно»),
«Добавки» (по желанию) → bottom sheet с обязательным выбором без цены (radio) и добавками
(степперы до `maxCount`, вариант «Без …»), sticky CTA «В заказ · 370 ₽ · 1 шт.».

Проверено вживую: 300 мл + кокосовое + корица + ваниль = **370 ₽**, состав
«300 мл · Кокосовое · С корицей · Ваниль» — как в эталоне.

### 10.3 Корзина (`/cart`)

Отдельный экран: адрес точки, блок «Где заберёте · Изменить», «Скидки и бонусы» (подарок/ваучеры —
показ, касса применяет), строки с составом, «− 1 +», «Изменить» (открывает карточку товара), «Удалить»,
«Позиции / Итого — оценка», sticky «Отправить в кофейню» + «Добавить ещё».

Состав уходит в заказ: `preorder_item_modifiers` получает `milk` / `choice` / `addon` с названием и ценой
(проверено в БД после живого заказа).

### 10.4 Выбор кофейни (`/pick-store`)

Первый экран, если точка не выбрана: список с адресом, часами и «Открыто/Закрыто», закрытая точка
недоступна, «Найти ближайшие» (геолокация, сортировка по расстоянию при наличии координат),
«Забрать здесь». Закрытая кофейня также блокирует отправку заказа.
