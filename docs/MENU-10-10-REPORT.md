## 2. Бонусы: как считаются деньги

Правило одно и живёт **на сервере**: `POST /api/orders/quote` → подписанный `quoteToken` →
`POST /api/orders` с этим токеном. PWA только показывает цифры.

```
SKU (объём) + платные модификаторы (молоко, сиропы, топпинги)  → subtotal
− подарок / ваучер / кэшбэк (одно правило за раз)              → total
```

- Цены модификаторов берутся из `modifiers`, а не из тела запроса: клиент присылает только id.
- Выключенный модификатор в сумму не входит — касса посчитает по своему каталогу.
- `quoteToken` живёт 10 минут и привязан к гостю (`uid`) и сумме: состав поменялся → `409 quote_stale`.
- Резерв льготы пишется в `loyalty_reservations`, касса потребляет его по номеру заказа (`sc.ord`),
  отмена заказа возвращает резерв (`status=EXPIRED`).

Проверено вживую: подарок 6-й стакан → корзина «Итого со скидкой 0 ₽» →
заказ `quote_total=0`, `benefit_json={"kind":"gift",…}`, резерв `RESERVED` → отмена → `EXPIRED`.

## 3. Что изменилось в API

| Метод | Путь | Что нового |
|---|---|---|
| POST | `/api/orders/quote` | `items[].modifiers[]` (цены серверные), `available` (подарок/ваучеры/кэшбэк) |
| POST | `/api/orders` | `quoteToken`, `409 quote_stale`, `benefit`/`quoteTotal` в ответе |
| POST | `/api/orders/:id/cancel` | освобождает резерв льготы |
| GET | `/api/directory` | `soldOut`, `mediaType/videoUrl/posterUrl`, `hours` (7 дней), `hasVolumes/priceFrom` |
| GET | `/api/directory/config/:id` | `mediaType/videoUrl/posterUrl` + объёмы/молоко/добавки |
| GET | `/api/directory/geo` | точки с координатами для «ближайших» |
| GET | `/api/push/public-key` | VAPID-ключ (без авторизации) |
| POST/DELETE | `/api/push/subscribe` | подписка гостя на «заказ готов» |
| GET | `/api/admin/preorder/orders` | `benefit`, `quoteTotal` — кассир видит, что идёт подарком |
| PATCH | `/api/admin/stores/:id` | `hoursJson` — часы по дням (7 значений, `null` = выходной) |
| POST | `/api/admin/products` | `mediaType`, `videoUrl`, `posterUrl` |

## 6. Живой прогон (что именно нажимали)

Backend `tsx src/index.ts` на копии БД, PWA `vite` на `:5173`, админка на `:5176`.

1. Онбординг → карта выдана, титул показывает прогресс стаканов.
2. `/menu` → `5 позиций`, «Популярное», бейджи «Хит»/«Новинка», «Матча латте» — `disabled`.
3. `/pick-store` → схема с двумя точками, «Google · Apple · Яндекс», «Открыто · до 20:00`,
   после выбора — «Маршрут · Яндекс» и «На карте».
4. `/search` → «кап» → «Найдено: 1», история запросов сохраняется.
5. `/menu/181` → добавки: Ваниль +40 ₽, Корица +20 ₽ → кнопка «В заказ · 320 ₽».
6. `/cart` → «Изменить» → вернулись с восстановленным выбором, «Сохранить · 320 ₽» → строка заменена, не задвоилась.
7. Бонус: «Подарок — 6-й стакан −260 ₽» → «Итого со скидкой 0 ₽» → отправка → заказ `draft`,
   `quote_total=0`, резерв `RESERVED`; «Отменить заказ» → резерв `EXPIRED`.
8. Медиа: загрузка `mp4` в админке → `<video>` на карточке товара PWA, в сетке — постер.
9. Админка `#/cash` → «Кофейни в приложении»: 7 дней, воскресенье — «выходной».
10. Админка `#/menu` → карточка товара: переключатель «Фото/Видео», кадр-обложка, загрузка файла.

## 7. Что осталось за пределами репозитория

| Пункт | Кому | Почему нельзя закрыть здесь |

| Касса принимает заказ с бонусом и печатает состав | агент `evotor-app` | другой репозиторий и сборка APK |

| Реальные фото/видео товаров | владелец | контент, не код |

Пока APK не обновлён, PWA **честно** пишет: «Финальная цена и чек — на кассе»,
а бонус в заказе помечен как резерв — начисление не выдумывается.
