# Редизайн клиентского PWA 6.7 Coffee

## Что сделано
- Главная карта ориентирована на прогресс и CTA показа QR.
- Добавлен fullscreen `/card-qr`: только подписанный `best.token`, крупный `cardCode`, статус сети/последней синхронизации, best-effort Screen Wake Lock.
- Нижняя навигация сведена к «Карта / Меню / Ещё»; история, профиль, акции и приглашение доступны из «Ещё».
- Добавлена история подтверждённых сервером событий из `/api/sync/history?limit=30&cursor=`; limit ограничен 50, авторизация обязательна.
- Синхронизация клиента защищена single-flight; stale и отсутствие сети показываются раздельно.
- Cashback UI указывает, что списание возможно у бариста на кассе. Каталог по-прежнему строится из `/api/directory`.

## Контракт истории
`GET /api/sync/history` требует Bearer JWT. Возвращает `items` и `nextCursor`; курсор — offset для простого ограниченного paging. Источник — `loyalty_ops`, `loyalty_ledger`, `cashback_ledger`; только текущий пользователь/его card_id. Статус каждой строки `confirmed`. Клиентские pending receipts не включаются.

## Деньги
`users.cashback_balance` и `cashback_ledger.amount` — копейки. `formatRub(450)` отображает `4,50`, `formatRub(400)` — `4`. `loyalty_ops.result_rub` в истории отображается как рубли.

## Ручная проверка
- iPhone Safari: Share → Add to Home Screen, открыть карту офлайн после первого запуска, проверить safe-area и fullscreen QR.
- Android Chrome: install prompt, QR fullscreen, сканирование QR реальным сканером Эвотор.
- Проверить card QR и invite QR как разные payload; проверить номер карты fallback.
- Отключить сеть: не должно появляться локальное начисление; должен отображаться timestamp.
- История должна содержать только подтверждённые события; проверить пользователя с пустой историей и страницу «Показать ещё».
