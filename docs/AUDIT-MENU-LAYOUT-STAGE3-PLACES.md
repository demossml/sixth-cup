# Макет меню — режим «Места» (задача 3.3, частично)

Продолжение [AUDIT-MENU-LAYOUT-STAGE3.md](./AUDIT-MENU-LAYOUT-STAGE3.md). Сделан **режим «Места»**: правка
содержимого списком, без холста. Секции и позиции стали редактируемыми, лист пересобирается движком сам.

Зона: `backend/` + `frontend-admin/`. Флаг `VITE_MENU_LAYOUT_V2=1` включает новые действия.

## Критический фикс по пути

`docPayload` (клиент) собирал документ только из `pages[].blocks` — **секции при сохранении стирались**.
Теперь в payload уходят `schemaVersion`, `sections` и `template`. Без этого любая правка на холсте
уничтожала бы раскладку, добавленную в этапе 2.

Так же `layoutView` (backend) отдавал клиенту только резолвнутые страницы: секции до редактора не доезжали.
Теперь `layout.doc` содержит `schemaVersion` и `sections` вместе с блоками.

## Что можно делать в «Местах»

| Действие | Как |
|---|---|
| Переименовать секцию | поле заголовка прямо в списке |
| Переставить позицию | ↑ / ↓ внутри секции |
| Убрать позицию из меню (не удаляя) | иконка глаза |
| Удалить позицию | корзина |
| Добавить позицию из каталога | клик по товару в «Каталоге» — при включённом v2 и наличии секций позиция уходит в первую секцию |
| Пересобрать лист вручную | ссылка «Пересобрать лист» (появляется при наличии секций) |

Порядок операций при правке: `PUT` с секциями и `baseRev` → `POST /layout` → редактор берёт готовый документ.
Так `/layout` всегда читает уже сохранённые секции, а не устаревшую копию из БД.

Позиция из каталога приходит с объёмами (`sizes` из `prices`), поэтому «Корица» сразу печатается
тремя ценами — руками ничего дублировать не нужно.
