Git в архиве отсутствует: сравнение с исходником возможно только по распакованному архиву (`git status` не выполнялся и не утверждается).

## 1. Карта проекта

Стек: npm workspaces + turbo; `backend` (Hono + better-sqlite3, zod, sharp), `frontend` (клиентский PWA, **не трогаем**), `frontend-admin` (Vite 5, React 18.3, TS 5.6, Tailwind 3, react-router-dom 6.27, lucide-react 0.460). Админка — отдельный SPA с `HashRouter`, один entry (`frontend-admin/src/main.tsx`), собирается в `frontend-admin/dist`. Backend отдаёт её по заголовку `Host` (`admin.*` или `ADMIN_HOST`), клиентский PWA — по остальным хостам; API `/api/admin/*` общий процесс (`backend/src/app.ts`). Service Worker у админки **нет** (в `frontend-admin/public` только manifest и иконки).

Авторизация: статический токен в заголовке `X-Admin-Token` (`localStorage['admin_token']`). Три роли по трём env-токенам: owner (`ADMIN_TOKEN`), manager (`ADMIN_MARKETER_TOKEN`), viewer (`ADMIN_VIEWER_TOKEN`, только GET). Сравнение через `timingSafeEqual`, rate limit неудачных попыток (30 за 15 мин на IP) в таблице `rate_limits`. В production без `JWT_SECRET`/`ADMIN_TOKEN` сервер не стартует.

## 5. Что проверено и не вызвало замечаний

SQL-запросы параметризованы, сортировки в `/customers` — через whitelist; LIKE экранируется; CSV защищён от формульной инъекции (`toCsv`); `Content-Type`/имена файлов в `/uploads` ограничены regex (traversal закрыт); секретные поля маскируются в аудите; `onError` не отдаёт stack trace; зависимость от rate-limit таблицы устойчива; bulk-правка с `dryRun` и транзакцией; оптимистичная блокировка в `PATCH /products/:id`; `useApi` отменяет запросы (`AbortController`) и не обновляет устаревшие ответы; повторный клик защищён `loading`/`busyId` в основных формах; мобильная раскладка без горизонтального скролла на всех 13 экранах.

## 6. Ограничения аудита

Данные тестовые (демо-seed + 30 синтетических клиентов); операции, чеки, графики и экраны Evotor без реальных данных не нагружались (нужен токен и боевые документы).
