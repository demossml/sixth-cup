## D. Подсистема добавок

Полный разбор — [ADDONS-ARCHITECTURE-AUDIT.md](./ADDONS-ARCHITECTURE-AUDIT.md).

Ключевое:

- **OID не нужен**: интеграция адресует товары UUID; parent-связь передаётся как `parentUuid` из `product_store_links`. Добавление OID-колонки создало бы поле без источника значения.
- **Правила фискализации соблюдаются структурно**: платная опция без пер-точечного UUID отдаётся с `available: false`; zero-опция не имеет ни `productId`, ни `evotorUuid`, ни цены.
- **A1 закрыт**: перенос идёт только из товаров, уже лежащих в «Добавках»; розничные позиции с тем же именем не затрагиваются, для остальных создаётся отдельный товар-добавка. Привязка уникальна (A2).

## J. Миграции

- Схема изменена **аддитивно**: `evotor_stores.sync_enabled` (колонка с дефолтом 0, старые БД догоняются `ALTER` в bootstrap).
- Дедупликация категорий выполняется в коде при старте, а не SQL-миграцией: корректная Unicode-нормализация в SQLite невозможна. Точные дубли схлопываются, товары и группы переносятся, лишние строки удаляются; при отсутствии дублей операция ничего не делает.
- Обратимость: удаление дубликата категории не восстанавливается автоматически, но данные (товары) не теряются — они переносятся в оставшуюся категорию.
- Проверено на копии реальной БД: 0 «осиротевших» ссылок после применения.
