# Админка: перенос на дизайн-прототип `coffee.html` (Phase 3)

## Что сделано
- `frontend-admin/index.html` теперь — разметка прототипа 1:1 (CSS идентичен). Логика: `public/ui/sc-api*.js` (данные и токен), `coffee.js` (интерфейс прототипа, подключён к API), `sc-bind.js` (подстановка реальных чисел в статичные блоки).
- Прежняя React-админка сохранена и доступна по `/classic.html` (кнопка «Открыть /legacy» в Система → Опасная зона).
- Все разделы работают с реальными данными: Сегодня, Операции (детали чека, период, CSV), Клиенты (поиск, карточка, телефон, ваучеры), Меню (товары, размеры → product-groups, чашка, массовые действия, группы, схемы + редактор, добавки, фото), Касса (опрос, sync, токены), Склад, Инвентаризации, Закупки (накладные, оплаты, заказы, возвраты, сверки, банк), Сотрудники (график, пожелания, привязка), Контент/ваучеры, Рефералка, Аналитика, Сравнение, События, Ассистент/ИИ, Система (журнал, логи, настройки ИИ).
- Токены и роли: тот же `X-Admin-Token` и ключ `admin_token`; наблюдатель — только чтение; менеджер не может выдавать ваучеры всем и менять ИИ.

## Бэкенд (только добавления, существующие маршруты не менялись)
- Миграция `024_studio_gaps.sql`.
- Новый модуль `modules/admin/studio.ts` (монтируется в `routes.ts` ПЕРЕД `adminStock`, иначе `/inventory/:id` перекрыл бы `/inventory/overview`; на это есть тест).

- Контракты для кассы/PWA/Android не менялись. График сотрудников пишется в формате `work/off` — как читает `/timesheet`.

## Проверки
- `tsc` (backend, frontend-admin) — OK; `npm run build` — OK; vitest: 128 прошли, 2 падения в `poll-service.test.ts` (они были до моих изменений, поллинг не трогался).
- Playwright: 16 экранов без ошибок консоли на заполненной и на пустой БД; E2E записи: товар с размерами, чашка, группа, схема, сотрудник, график, опрос/sync точки.

## Известные ограничения
- Выручка в аналитике считается по чекам с картой лояльности (так же, как раньше); чеки без карты учитываются только числом.
- Опрос кассы без токена Эвотор отвечает ошибкой (честно показывается в тосте).
- Банк: выписка загружается вручную, автосвязывание по поставщику/номеру.
- Сотрудники в аналитике — только если кассы привязаны к сотрудникам; иначе показывается пустое состояние.
- Не реализовано: повторная обработка отдельного чека, предпросмотр PWA, связь заказа поставщику с приходом (статус заказа вручную), «Свой диапазон» в аналитике.
